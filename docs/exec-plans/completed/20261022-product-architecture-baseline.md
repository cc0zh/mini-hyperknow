# mini-hyperknow 产品与架构文档基线

## 目标、范围与风险

- 目标与验收标准：把用户讨论确认的产品范围、业务状态、目标架构、数据与接口契约、拒绝 Mock 的真实验收要求落为相互链接的设计文档；通过文档骨架、链接及范围一致性检查。
- 包含：参照 ActSpace 设计文档的组织方式，在本项目建立可实施的设计基线，更新 README、架构入口、产品原则和质量状态，记录参考证据与实现缺口。
- 不包含：业务代码、依赖安装、应用启动、真实模型调用、已有 Mock 测试迁移或删除；本次文档通过不等于业务已实现或真实验收通过。
- 已确认产品范围：文字目标 → 澄清 → 课程生成 → 课程路径 → 无语音白板与课堂问答 → 练习／考核／项目 → 记录与继续学习；个人单用户、桌面中文、简历项目、业务优先。
- 已排除：语音、资料上传／解析、知识库、独立聊天、独立深度学习、集市／多人社区、支付订阅、企业级权限与安全治理；不引入无证据的新教学规则。
- 风险及缓解：Clone 不是原站全部事实；将用户确认、源码事实、推导补齐和待核实项分开。现有内核只有同步调用与内存上下文；目标能力不得写成已实现。
- 已有授权：编写项目产品设计和架构等文档，可修正受影响的文档入口；不修改只读参考仓库，不操作凭据，不执行收费调用。
- 关联入口：[设计索引](../../design-docs/index.md)、[架构总览](../../ARCHITECTURE.md)、[质量状态](../../QUALITY_SCORE.md)。
