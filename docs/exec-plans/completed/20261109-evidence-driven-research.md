# Evidence-driven course research

## Goal, scope, and risk

- Goal and acceptance criteria: make every research finding traceable to exact, successfully read source passages; let one local research Agent choose among Tavily and Exa retrieval; make research evidence available to course planning and downstream teaching generation; verify the changed behavior with deterministic tests and existing learning evaluations.
- Included: a typed question/claim/evidence contract; exact-quote validation against saved page excerpts; provenance-preserving Tavily and Exa search/content adapters; targeted evidence context for blueprint and unit expansion; scope-sensitive research on blueprint feedback where the current lifecycle supports it; focused tests and documentation updates.
- Excluded: deployment, distributed infrastructure, generic provider/plugin registries, model training, broad security changes, changes to grading semantics, and paid live-model or search calls without explicit run authorization.
- Risks and mitigations: old persisted reports predate claim-to-passage relations, so preserve their stored JSON and distinguish legacy runs from newly validated reports. Search-provider scores are not comparable, so retain provider identity and rank evidence only after normalization. Do not treat model-produced support labels as proof; validate exact quote membership and retain semantic grounding evaluations. Keep the single local Agent as the only research controller.
- Authorization and confirmation boundaries: local implementation and checks are authorized. Do not send paid provider requests, publish, deploy, push, create a PR, or commit.
- Related design documents, product specs, or quality items: `docs/design-docs/web-research-agent.md`, `docs/design-docs/course-blueprint-workflow.md`, `docs/design-docs/agent-workflows.md`, `evals/README.md`.
