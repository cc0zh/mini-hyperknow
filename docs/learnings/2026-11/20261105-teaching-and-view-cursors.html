课堂播放器为什么需要
“教学位置”和“查看位置”？

课堂讲到了第七步，学生拖回第三步查看一张图。如果我们只存一个 cursor，就必须在“让学生回看”和“保护已经确认的学习位置”之间二选一。解决办法是把事实、视图和提问锚点分开。

教学位置回答“服务端已经确认讲到了哪里”；查看位置回答“学生现在看哪里”；问题锚点回答“这次问题指向哪里”。它们有关联，但不是同一个事实。

先试一次回看

这是离线状态设计演示，不连接应用或模型。点击回看后，板书和右侧讲解会一起切换，而教学进度不会倒退。

当前所看步骤的解释

真实产品中，“确认下一步”必须先经过服务端事务与版本校验，不能先更新画面，再假定写入会成功。

三个位置，各自负责什么

位置持有者规则
progress.cursor服务端 SQLite只能保持或前进一步。它限制已讲前缀，也决定什么时候可以结课。
viewCursor前端查看状态不能超过确认位置；回看时同时驱动白板和讲解，不改教学事实。
anchor_step_id / anchor_object_id随问题保存只能引用已讲内容。回答“这条箭头为什么回到这里”时，需要知道具体是哪条箭头。

最容易出现的两个错误

错误一：只让白板回看，右侧仍显示最新讲解

这会让两块各自“正常”的组件组合成一个错误解释：旧图旁边出现新结论。修复点是共享的查看位置，而非给两个组件各加一个回看开关。

// 相同查看位置，控制同一个教学步骤的两种表达
const viewedStep = script.steps[viewCursor]
renderBoard(script.steps.slice(0, viewCursor + 1))
renderNarration(viewedStep.narration)

// 保留独立的权威事实，不在回看时发进度回退命令
const confirmedStep = snapshot.progress.cursor

错误二：把提问锚点当成教学位置

学生可以在第七步时问第三步的图。正确做法是保存两个事实：教学暂停在第七步，这次问题指向第三步。明确继续时回到第七步，既不重复讲第三到第六步，也不丢掉问题引用。

与播放和相机的关系

  • 播放时钟只根据确认位置推进；进入回看应先停止自动推进，避免阅读时画面被抢走。
  • 手动平移只改变相机，不改变上述位置；“回到当前讲解”同时恢复教学位置与相机跟随。
  • 页面刷新读取权威位置，但本地播放始终暂停。数据库里的 playing 是历史意图，不是恢复时的自动播放指令。
  • 对象 ID 表达图中的身份，坐标只是排版结果。相机移动、字体重排或窗口变化不应使引用失效。

自检

  1. 学生回看时，自动播放继续推进了两步，界面应该保持哪个位置？为什么？
  2. 问题回答在刷新后才完成，需要哪些持久化事实才能回到原教学位置？
  3. 同一张图被重新排版，问题应该绑定坐标还是对象 ID？

这类分离同样适用于日志回放、调试器、视频审阅和实时仪表盘：实时事实、历史查看和用户标注常常有不同生命周期。
