量到容器宽，不代表内容已经入镜

白板已经缩到一屏，为什么公式末尾仍然消失？相机解决的是「纸面能否入镜」，但纸面里面的公式还可能溢出。两者是不同层级的几何问题。

先看失效方式

一个伸展的块级容器总是占满可用宽度。其内部内容即使很长，容器的 offsetWidth 也不会跟着变长。拿这个数做适配，会得出一个错误结论：「已经放得下了」。

停止条件 = 轮次到达上限，或者截止时间已过；程序负责真正终止。

这是离线DOM几何演示，不加载KaTeX、不调用模型，不是产品的真实生成验收。先切换测量方式，再拖动缩放，观察同一段内容是否始终完整。

把白板缩放从测量中消掉

range.selectNodeContents(ink)
canvasScale = box.getBoundingClientRect().width / box.offsetWidth
naturalWidth = range.getBoundingClientRect().width / canvasScale
fit = Math.min(1, availableWidth / naturalWidth)

getBoundingClientRect() 是变换后的屏幕像素；clientWidth／offsetWidth 是布局像素。直接比较它们，会把相机缩小误认为内容本身变短。先统一坐标系，再计算适配比。

为什么纯估算仍会少一行

125像素的表格单元格、19像素的中文字，看似能装下6.58字，但一行实际上只能容纳六个完整字符。13字需要三行，不是把247像素总宽除以125得到的两行。计算还要留意标题、内边距、合并边框、语言标签和全局段落行距。

  • 容器、内容和相机必须分别测量，再统一单位。
  • 量真实内容不能依赖容器自动伸展的尺寸；Range适合已有DOM内容。
  • 字体加载和宽度变化后重新测量；观察宽度而不是每次高度变化，避免反馈循环。
  • 先以结构测试检查几何，再用真实浏览器检查裁字和内部滚动条，不能互相代替。
自检：整张纸入镜，能证明所有公式已完整显示吗？

不能。纸面内部可能有独立溢出的元素、滚动容器或SVG裁切，需要继续检查实际墨迹。

自检：用Range量到的宽为什么要除以相机缩放？

Range提供屏幕坐标；用于适配的可用宽度来自布局坐标。除去相机变换后才能比较同一单位。
