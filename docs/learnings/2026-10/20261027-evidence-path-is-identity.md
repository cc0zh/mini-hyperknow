# 收纳目录之前，先分清展示路径与证据身份

一个目录看起来只是文件夹，却可能已经参与运行身份。把它移动到“更整齐”的地方，不一定是无害重命名。

本项目后端以解析后的数据库路径生成storage_id，恢复还核对数据库路径及device/inode。即使把同样的文件复制回同一个字符串路径，inode变化也可能不再是原实例。更不能修改冻结JSON中的路径来“修复”恢复：source已进入证据与评分摘要，修改会破坏原始事实。

因此应分两层处理：

- **展示层**可收敛为固定report.html和一个总入口；它是可重建视图，不应决定原始成绩。
- **证据层**保留身份与原字节；相对引用的Trial和轨迹可以成组收纳，绑定路径的数据库则留在原位。

减少文件噪声也不等于删除历史。对同一来源计算内容摘要时排除纯展示生成时间，重复导出可以复用快照；一旦证据、评分或状态改变，必须保留新快照。

迁移时先记录from→to和文件哈希，再移动，最后核对原文件字节、数据库实例、原评分及入口链接。这样改善的是人的阅读成本，而不是悄悄改写审计来源。
