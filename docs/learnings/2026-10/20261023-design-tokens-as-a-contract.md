# 设计令牌不是「变量表」，而是一份契约

从 [设计令牌层改造](../../histories/2026-10/20261023-2340-design-token-foundation.md) 提炼。

## 是什么

设计令牌（design token）是把颜色、字号、间距、圆角、动效这类视觉决定的**取值**抽成命名变量，让样式表引用名字而不是直接写值。它看起来只是把 `#29342c` 换成 `var(--ink-900)`，真正的作用却是**把「这个值是什么」和「这个值用在哪里」分开**。

## 为什么需要

改造前仓库里有约 300 个不同 hex，散在 7 份 CSS 中，带来三个具体问题：

1. **同一语义多种写法**：正文色同时出现 `#242c37`、`#28342e`、`#29342c`、`#2d4136`，肉眼几乎分辨不出差别，换主题时却必须逐个找。
2. **跨页不一致**：工作台拿蓝色当主色，其余页面是 sage 绿，用户会以为换了产品。
3. **深色模式无处落脚**：颜色是一堆散落字面量，没有可以整体替换的抓手。

令牌层把这三件事一次解决：改主色只动 `--sage-700`；深色模式只是换 ramp；新页面必须从已有名字里挑，天然保持一致。

## 怎么分层

关键是**两层命名**，不能只有一层：

```css
/* 第一层：原始色板，只描述「是什么颜色」 */
--sage-700: #4a5c3e;

/* 第二层：语义别名，只描述「用在哪」，指向原始色板 */
--accent: var(--sage-700);
--text: var(--ink-900);
--surface: var(--paper-1);
```

页面样式**只消费第二层**。收益在深色模式下最明显：深色主题必须把 sage 调亮才能当前景色用，

```css
@media (prefers-color-scheme: dark) {
  :root {
    --paper-0: #15181a;   /* 换 ramp */
    --sage-700: #b3c99a;  /* 深色下 sage 必须变亮 */
  }
}
```

因为 `--accent` 是 `var(--sage-700)`，它会自动跟着变。反过来，如果页面直接写 `var(--sage-700)` 并把它当背景色，深色下就会变成"浅绿底 + 白字"，可读性直接崩掉。

## 常见陷阱

**一层命名。** 只写 `--green-dark` / `--green-light`，页面里到处 `var(--green-dark)`。这比写死 hex 强，但不解决换肤：名字描述的是颜色本身而非用途，深色下到底该变亮还是变暗说不清。

**语义别名互相引用成环。** `--text: var(--ink-900)` 可以；再让 `--ink-900: var(--text)` 就会让整条链被浏览器判为无效属性，回落成 inherit。症状是"某些文字莫名变成浏览器默认黑"，极难排查。

**深色模式把「固定的东西」也换掉。** 本项目板书区是刻意例外：`--slate-*` 在深色下保持不变，因为课堂应该像一张白纸。机械地让所有颜色跟随主题，白板会变黑板，手写字体与 Mermaid 配色全部失去对比。判断标准是**这个元素在现实里对应什么材质**，而不是"它是不是颜色"。

**把 alpha 值当成颜色写进令牌。** `#22282e0a` 这类带透明度的阴影色在深色下完全失效——半透明黑叠在深色背景上等于没有。阴影要成组定义成 `--shadow-1..4`，两套主题各给一组，而不是让页面自己拼。

**把字号当成排版。** 令牌里有 8 级字阶不代表排版就对了。改造前满屏 `9px` / `8px` / `7px`，即使全部换成语义令牌，只要 `--fs-2xs` 定义成 9px，问题就还在。令牌的价值是把"最小字号"变成一个可以被质疑、被统一修改的决定，而它本身不会替你做出正确决定。
