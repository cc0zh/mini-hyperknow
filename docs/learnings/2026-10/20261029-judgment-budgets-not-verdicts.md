# 为什么“没超过预算”仍可能没有评分结果

评测模型的token预算不是只给最后那段JSON用的。尤其使用reasoning模型时，一个请求可以成功计费、严格用满输出预算，却连一个最终答案字符也没生成。

## 先分清两道门

```text
完整输入的本地估计 + 预留输出 <= 上下文预算？
  否 → 不发送请求；证据不截断；结果为insufficient
  是 → 先保存in_flight，再发送一次
          ↓
供应商最终正常结束，且产生可严格解析的判据JSON？
  否 → 保存原始响应与usage；结果仍为insufficient
  是 → 逐项核对证据与判据，不因JSON有效就全部通过
```

**上下文预算**控制能否发送完整请求；这里的token数是保守估计，不等于供应商实测。**输出预算**是供应商completion上限，可能同时包含reasoning和最终content。二者都只是资源约束，不是教学结论。

## 两种失败需要不同解释

这次真实长答卷评分，4096 completion tokens全耗在reasoning，`finish_reason=length`，最终content为空。这证明请求有实际用量，却没有可用判卷；不能因为HTTP成功、usage没超限就报告教学通过，也不能断言教学内容错误。

另一份真实讲义的完整输入本地估计115023，加16384预留为131407，超过96000本地门槛。此时没有评分请求、没有该次评分费用；这不是供应商拒绝了131407 tokens，也不证明其真实窗口不足。框架不能把估计当成实测，更不能偷偷删掉讲义正文来换一个“通过”。

## 如何修，而不改变实验叙事

1. 原失败、原始响应和用量保留，不重跑教学内容。
2. 确认原响应是已知结束，而非仍在途的未知提交；未知提交不能自动重发。
3. 明确选择新模型／输出／上下文预算，**追加**新的评分attempt，而不是覆盖旧判定。
4. 报告计划配置与最新实际配置的差异；比较时不能将不同judge配置当成产品进步。
5. 用同配置检查控制样本，但仍不把作者控制通过写成人工校准完成。

如果供应商报告的输出usage本身超过请求限制，这又是第三类问题：已知预算违约。应记录exceeded并停止当前执行的后续收费请求，剩余单元not_run；不能把它和“正常用满预算但没答完”混为一谈。

## 自检

- HTTP 200、completion=4096、content为空，能否证明教学失败？不能，只能证明本次评分未完成。
- 本地上下文门禁拒绝后，能否把usage填0并声称供应商不收费？未发出的这次没有模型调用；历史或其他在途费用仍未知，不能一并归零。
- 扩大judge预算后通过，能否称教学版本改善？不能，冻结答卷没变，改变的是测量配置。
