# 可选方法与显式动作：不要让文案承担执行协议

## 方法不是通行证

Skill适合承载某些任务才需要的专门方法。把“先加载任何Skill”作为回答或创建内容的
前置条件，会把方法选择变成与任务无关的通行证：即使模型已经能直接回答，执行器仍然拒绝。

删除不合适的方法包不等于删除方法系统。更简单的边界是允许空注册表，无目录时不注册
加载工具；有方法时仍检查可信路径、冻结正文和版本摘要，并记录实际使用。工具权限始终
由宿主决定，不能因加载文本而扩大。

## 可读文字不是可靠命令

“继续看例子”既可能表示进入原计划下一步，也可能表示继续解释当前步骤。通过字符串
猜测会让外观相似的按钮走不同状态校验。把建议定义为`{label,text,action}`，让文案负责
表达，让`message/continue`负责意图；后端再检查是否存在合法下一步。

提示模型正确选择动作，不能代替后端检查；类型声明也不能代替真实运行契约。两者是
必要分工，而非应该消除的重复。

## 重构时如何验证

- 文件搬家先核对提示内容和Schema；教学行为调整单独明确，避免把移动误当质量改善。
- 测空目录，也测非空目录能真实加载并落盘；只测“删掉了名字”会误删整个可选能力。
- 同时测合法推进与不存在下一步的拒绝，不用一句包含“继续”的文案模拟状态。
- 待确认命令恢复保留原命令身份；刷新恢复不是重新生成一条同内容命令。
- 本地结构/存储检查通过，不等于真实模型教学更准确。
