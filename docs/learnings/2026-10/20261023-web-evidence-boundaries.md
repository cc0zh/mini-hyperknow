# 网页工具：搜索结果不是已读证据

## 为什么要分开

搜索摘要适合寻找资料，但可能过时、截断或脱离上下文。如果把搜索结果直接标成“已阅读”，模型便能引用一个从未取得正文的URL，看起来有出处，实际无法追溯。

一个更清晰的边界是：**搜索发现候选，阅读形成证据，报告引用证据ID。**

## 三步实现

1. 搜索只保存URL、标题和摘要，不产生可引用的source_id。
2. 抓取成功、提取正文并保存后，由代码生成source_id；保存最终URL、抓取时间、是否截断以及实际摘录的哈希。
3. 报告校验每条结论引用的ID是否属于本次已读集合。无效引用进入有限修复，不能补一个看似可信的URL来通过。

这只能证明“资料确实进入生成上下文”，并不证明“资料支持模型的这句话”。后者仍需要人工核查或额外的内容评估，不能把引用校验当事实正确性保证。

## 公网页面为何也需要网络边界

URL写着域名，并不意味着连接目标是公网。DNS可能解析为私网地址，重定向也可能跳到本机；只在请求前检查一次URL字符串不够。

抓取器应校验所有解析结果、连接固定已验证的IP，同时保留原主机名的TLS证书校验和SNI。每次重定向重新检查，不能让HTTP库默默跟随。还需要限制响应字节和时间；文本截断必须明确标记，否则模型会把一个摘录误认为全文。

## 自检

- 搜索到某URL但正文请求失败，报告还能把它称作“已读来源”吗？不能。
- source_id有效能证明结论正确吗？不能，只证明对应页面已进入输入。
- 抓取前检查DNS、随后让客户端重新解析域名，能防DNS rebinding吗？不能，应将连接绑定到已验证的地址。
