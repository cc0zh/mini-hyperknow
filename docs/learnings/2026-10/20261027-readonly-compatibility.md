# 保留旧数据，不等于保留旧执行器

## 为什么容易混淆

系统升级后，常见理由是“旧实验还要查，所以旧代码不能删”。这里其实混合了三种不同需求：

- **保留事实**：原回答、评分、轨迹和费用记录不能丢。
- **继续读取**：新入口能够打开旧格式，说明它是什么。
- **继续执行**：旧流程仍能提交任务、调用模型和写入结果。

前两项不天然要求第三项。把它们绑在一起，就会为查阅历史永久维护两套可产生副作用的系统。

## 怎么收敛

先画出旧执行器被谁引用：新版可能仍借用其中的URL校验、只读数据库连接等安全函数。直接删文件会误伤新版；只删命令名又留下完整旧执行器，也没有消除维护负担。

把真正共享的安全能力迁出；把旧格式校验和历史摘要留成只读模块；删除旧提交、重评和样本写入路径。日常只有一个CLI，历史格式由它明确分流读取，而不是伪装成一次新版运行。

## 两个关键边界

**迁移题目，不等于迁移实验事实。** 旧Case可以显式转换成新任务，新实验重新执行；旧回答不能因此获得当时没有记录的检查点、代码版本或证据身份。

**只读兼容，不是偷偷修复历史。** 阅读时可以沿用原汇总口径披露预算超限，但不能把在途评分重新解析成已完成，不能自动重发模型请求，也不能写回历史文件。

## 怎么验证

- 旧命令明确拒绝，不能隐式跳到可能收费的新流程。
- 新入口不再导入旧执行器，安全检查仍有测试。
- 同一历史文件查看前后字节相同，评分状态和未知用量不变。
- 旧结果不能恢复、重评或直接混入新版版本比较。
