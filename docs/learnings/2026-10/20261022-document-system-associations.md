# 文档系统关联的生命周期设计

这次修复沉淀了两个可迁移的规则：文档系统的主要风险不是入口文件数量，而是状态迁移后引用是否仍然有效；不同记录的边界必须由模板和检查共同落实，不能只写在指南里。

## 计划归档不是简单移动文件

execution plan 从 `active/` 移到 `completed/` 后，执行记录、设计文档、history 和 PR 里的入链都可能失效。因此归档动作必须包含“搜索旧路径并更新入链”，模板不能把活动目录写死为永久地址。

## history 不应复制计划事实

有完整计划时，history 只保留诉求、结果和当前计划路径；没有计划时，history 才承载改动、动机和验证。用模板明确两个分支，可以避免计划和 history 后续各自更新而产生事实漂移。

## 机械检查的边界

Markdown 检查适合验证本地文件链接、标题锚点和代码围栏中的示例是否被误判；它不能判断正文语义，也不能替代设计评审。因此门禁应保护可机械验证的关系，长期设计仍由设计索引和任务收尾规则维护。
