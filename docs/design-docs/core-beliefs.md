# 核心理念

这些理念用于约束这个模板在项目早期的默认方向。

## Agent-First 的工作原则

- 人来定方向，Agent 负责执行和推进。
- 仓库内可追溯的知识，比私有上下文更重要。
- Agent 反复失败时，优先修脚手架和环境，不是继续加 prompt 压力。
- 短而稳定的入口文档，比越来越长的大 prompt 更可靠。
- 能变成机械检查的约束，就不要只停留在口头规范。
- 速度很重要，但无节制地堆积熵会迅速拖垮效率，所以要持续整理和收口。
- 编码行为要可验证：假设显式化、改动最小化、每步有检查——让人和 Agent 都能对结果负责。

## mini-hyperknow 的产品约束

- 还原参考产品的核心交互，不借工程重建重新定义学习产品；范围权威见[产品设计](product-design.md)。
- 优先真实业务和数据闭环，不用个人简历作品包装假成功，也不建设企业级平台。
- 模型生成内容，代码负责状态、计分和保存，不为使用 Agent 强加自主工具循环。
- 拒绝 Mock 测试和模板伪装；未验证能力如实标记，见[真实验证](real-validation.md)。
