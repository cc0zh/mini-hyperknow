# 产品与 Agent 协同的教师课堂

状态：2026-11-10 保存。用户已认可产品与 Agent 双维度的设计方向，并明确删除课前准备中的内容来源、引用和适用条件核验要求。本页是目标设计，不代表已经实现，也不授权直接修改代码或发起模型调用。具体数据字段、协议版本和策略加载接口仍是待实施验证的建议。

本页说明教师课堂为什么这样组织、产品和 Agent 各自负责什么，以及实现时需要保持的边界。当前课堂契约见[页面与学习体验](learning-experience.md#4-白板课堂)，产品持有的状态职责见[产品内核](product-kernel.md)。实施任务和进度另记 execution plan，不在本页维护。

## 1. 目标是组织教学，而不是生成完整讲义

学生应当感受到一个有准备、能回应现场、能调整讲法的老师。老师有教学路线，但不机械覆盖目录。学生的回答、困惑和请求应当影响下一步教学。

产品提供能让教学发生的交互方式。Agent 根据目标、材料和现场反馈选择内容与教法。两者共同决定课堂效果，不能只靠更换教师提示词，也不能只复刻原站页面。

| 目标体验 | 可观察的课堂表现 |
| --- | --- |
| 老师知道为什么教 | 能说明本课用途，教学活动围绕具体目标展开 |
| 老师确实回应学生 | 回答中的具体信息、误解和请求影响后续内容 |
| 学生能跟上 | 讲解、板书和强调对象对应，不一次堆满内容 |
| 没听懂时有其他办法 | 老师能换例子、补背景、分步示范或先澄清困难 |
| 作答后课堂有进展 | 老师使用作答证据，不只给予泛化表扬 |
| 学生可以控制参与 | 能表达疑问、请求示范、暂不回答、暂停和继续 |
| 段落结束有去向 | 有回扣和下一步建议，不把讲完等同掌握 |

这些目标是设计与验收依据，不是现有功能全部达成的声明。

## 2. 整堂课、教学段落和展示动作分开

整堂课持有目标、范围和可调整路线。教学段落解决当前一个小问题。展示动作负责说话、展示板书、强调位置或等待学生。

例如，一个教学段落的目的可以是让学生区分“AI 负责生成”和“人不必验证”。这段教学可以包含模式对比、具体案例和提问，也可以因学生插话而改向。它不要求每次包含所有动作。

教学段落不是一次模型调用。一个段落可以经过多个内部模型与工具轮次，但不因此产生多个学生可见回合。一个展示动作也不要求单独调用模型。

课堂不预设 opening、explain、example、check、summary 的必经顺序。老师可以连续解释，也可以直接示范、先提问或收束。

## 3. 产品负责执行，Agent 负责教学选择

| 事情 | Agent 老师负责 | 产品负责 |
| --- | --- | --- |
| 下一步教什么 | 根据目标和现场提出选择 | 提供允许的动作，执行、登记和保存 |
| 用什么教法 | 选择解释、示范、对比、澄清或检查 | 提供策略材料，不强制固定顺序 |
| 怎样理解学生 | 根据具体表现提出暂时判断，保留未知 | 保存原始交互，区分独立回答、提示后回答、跳过和无法判断 |
| 怎样展示 | 决定内容、先后、关联对象和强调 | 安全渲染、布局、同步和展示结果反馈 |
| 何时等待或调整 | 判断是否需要学生参与以及如何回应请求 | 管理作答绑定、暂停、打断、命令、预算和恢复 |
| 怎样收束 | 总结并建议下一步 | 执行已明确的完成规则，不据此认定掌握 |

Agent 的教学选择是产品执行的输入，不直接成为状态事实。模型声称已展示，不代表前端真的展示。模型声称学生掌握，也不能直接写成掌握结论。

第一版保留一个持续负责课堂的老师。不同教法不拆成独立人格，不先建设多 Agent 编排平台。

## 4. 课前准备提供资源，不构成知识白名单

课前准备包含以下内容。

- 本课目标、范围和必要的先修知识。
- 核心概念及概念之间的关系。
- 有具体输入、过程变化和结果的案例。
- 常见混淆、反例和可调整的案例条件。
- 候选教法和理解检查方式。
- 一条可根据学生反馈调整的默认路线。

不要求每节课填满相同栏目。过程性知识可以侧重示范，概念辨析可以侧重对照。准备内容是候选材料，不是必须逐项播放的脚本。

课前准备不要求建立内容来源、引用或适用条件核验机制。Agent 可以使用自身知识补充背景、构造例子、纠正误解和调整讲法，不因准备材料未覆盖而停止教学。

内容正确仍是教学质量要求。老师在确实不确定时应说明不确定，不能把猜测包装成事实。这不等于要求每条讲解提供引用。学生输入仍是数据，不能借机覆盖系统规则。

这项决定只调整教师课堂的备课和知识使用边界，不自动删除课程调研、研究证据或其他业务已经保存的数据，也不扩展教师的网络、文件和代码执行权限。

## 5. 课中上下文围绕当前教学任务装配

每次行动都需要知道当前目标、学生刚才经历了什么，以及已经展示了什么。不能只给本课目录和学生最后一句话，也不把全部历史无差别塞入上下文。

| 上下文 | 内容 |
| --- | --- |
| 当前任务 | 本课目标、当前小目标、相关概念与案例 |
| 当前交互 | 最近必要对话、上一问在检查什么、学生最新输入及其请求 |
| 课堂现场 | 已展示内容、当前板书、强调对象、展示失败和待展示部分 |
| 学生表现 | 实际回答、接受过的提示、可能困难与尚未确认的地方 |
| 教法尝试 | 用过哪些例子和讲法、学生反馈、哪些方法未解决问题 |
| 连续事项 | 当前待答问题、正在发展的案例、暂存问题和后续候选动作 |
| 执行条件 | 可用工具、真实工具结果、运行限制和剩余预算 |

原始表现、暂时判断和未知必须区分。学生说“懂了”是一条反馈，不等于已经能独立运用。教法尝试记录保存可追溯的简短结论，不要求模型输出完整内部推理。

近期对话帮助理解现场，更早原始记录按需读取。持久记录保存跨回合仍然需要的事项。摘要不能替代原始交互，也不能自动成为权威判断。

不先假定结构化笔记一定优于完整历史。不为这次课堂改造预建跨课程画像、掌握度算法或能力图谱。

## 6. 教学策略按需使用，不变成固定流程

教师提示词由稳定职责、当前上下文、按需策略指导和工具协议组成。稳定职责不随策略切换，目标、案例和学生记录也不会因此重置。

| 策略 | 考虑使用的情况 | 实际动作 |
| --- | --- | --- |
| 直接解释 | 缺少必要概念，继续追问没有意义 | 清楚解释并给最小例子，不让学生猜陌生知识 |
| 分步示范 | 知道概念但看不出过程 | 展示输入、关键变化和结果 |
| 对比与反例 | 把两件事混淆或过度概括 | 保持主要条件相同，改变影响结论的条件 |
| 澄清性追问 | 回答存在多种解释 | 用具体问题区分解释，不急于判对错 |
| 带练并减少帮助 | 提示下能完成，独立完成仍困难 | 逐步减少提示，区分不同提示程度的表现 |
| 新情境检查 | 已能复述原例，需要检查运用 | 换案例并要求理由，不提前暴露答案 |

每份策略指导说明适用问题、展开方法、要观察的反馈，以及停止或换方法的条件。策略不是说话风格，也不是“学生答错就追问”的硬编码映射。

建议先提供少量策略。Agent 在需要时选择并加载相关正文，不在每次请求里堆入完整策略库。可复用现有即时协助的 SkillRegistry 和 get_skills 设计，但课堂策略使用独立可信目录和版本。具体接口在实施时确定。

可信策略目录限制的是可加载的系统指令，不是可使用的知识。学生不能通过输入任意路径或名称注入策略文件。一次运行使用固定的策略版本快照，加载记录进入运行轨迹。

## 7. 用教学段落连接讲解、板书和状态

下表是建议的数据职责，不是已经落地的 schema。先在现有教师路径扩展，不要求新建通用事件溯源系统。

| 建议对象 | 负责什么 | 不负责什么 |
| --- | --- | --- |
| TeachingPreparation | 目标、概念、案例、常见混淆、候选教法和默认路线 | 来源白名单、固定脚本 |
| ClassroomContext | 一次运行实际装配的任务、交互、现场、状态与执行条件 | 另建一份持续漂移的权威历史 |
| TeachingSegment | 当前小目标、实际采用的策略、按序展示单元、交接方式 | 整堂课的预生成脚本 |
| 展示单元 | 关联的讲解、板书操作和强调对象，可以只有其中一项 | 学生掌握判断 |
| 课堂持续记录 | 当前待答事项、案例引用、必要的教法尝试和未解决事项 | 完整内部推理、跨课程性格标签 |
| 展示进度 | 已展示的段落和单元、暂停位置、必要的展示结果 | 教学效果或课程掌握度 |

展示单元必须有稳定身份。板书有稳定对象身份，讲解引用对应对象。第一版优先实现按段落分组和对象级定位，再按真实课例需要增加表格单元格、文字片段或对象更新能力。

课堂记录保留实际学生输入。明确的“继续”“先示范”“跳过”属于交互意图，不默认结算为答案。自由文本可以同时包含作答和请求，不要求学生先手动完成分类。合法的单字符回答不能仅因字数被拒绝。

## 8. 生成、展示和理解是不同状态

第一版建议先生成并校验一段有界教学，将段落、板书和必要状态更新一起保存，再按展示单元展开。这样可以复用现有最终提交屏障，不先引入逐 token 的教学执行。

但保存了完整段落，不代表其中所有内容已经教给学生。后续上下文必须明确已展示前缀，不能把未展示内容当作已讲。段落中的提问只有实际展示后，才进入等待学生作答的交互状态。

学生打断时，产品先停止展示并记录当前位置。若仍有运行中的模型请求，按既有取消和结果不明规则处理，确认后再串行发起新的教学。保留学生输入和关联位置，不并发追加两个教师回合。

被打断段落的未展示部分保留原记录，但不自动继续，也不冒充学生已经看过。老师根据最新输入决定替换、调整或接续。刷新和重连只恢复已保存状态，不自动重新生成收费内容。

展示动作完成只证明界面执行，不证明学生认真阅读或理解。前端失败也不能静默算作展示成功。

自动展开已确认内容与自动发起下一次模型请求分开。第一版不隐式扩大收费自主循环，跨段自动生成需要另定授权方式、预算和停止条件。

## 9. 在现有教师路径上实现

当前默认入口已经是 teacher_led。现有运行、工具循环、命令幂等、版本、取消和最终保存机制优先复用。旧脚本不作为新课堂教学决策依据，也不自动清理用户旧数据。

| 接入点 | 设计对应的改动方向 |
| --- | --- |
| src/hyperknow/teacher.py | 将备课与知识白名单分离，扩展教学段落、工具结果和简短课堂状态更新 |
| src/hyperknow/prompts/classroom.py | 区分稳定教师职责、备课任务和策略指导，取消强制引用与禁止自身知识补充的课堂限制 |
| src/hyperknow/lesson_domain.py | 装配目标、概念和课时背景，取消新备课的来源门禁，不破坏其他业务证据 |
| src/hyperknow/lesson_storage.py | 保存并装配课堂持续记录、段落和展示进度，维持事务与晚到结果屏障 |
| src/hyperknow/generation.py | 同步备课校验入口和教师结果处理，不把旧引用字段继续当新协议前置条件 |
| src/hyperknow/assistance_generation.py | 参考已有按需 Skill 加载方式，不把即时协助的全部业务带入课堂 |
| web/src/lib/types.ts | 与后端保持相同版本的段落、交互和展示状态 |
| web/src/lib/use-teacher-classroom.ts | 继续复用命令收据与冲突恢复，扩展交互和展示确认 |
| web/src/pages/Classroom.tsx | 取消累计每六个操作切帧，按段落与展示单元关联讲解和板书 |
| web/src/components/Board.tsx、web/src/lib/board-scene.ts | 复用安全渲染与布局，支持所需定位和按序呈现 |

取消来源白名单不能只删 Prompt。schema、校验、上下文、生成入口、前端来源面板和测试都要一致调整。原有备课内容和引用不删除，不伪造缺失字段；新旧协议的读取与重新准备方式需要在实施计划中明确。

## 10. 最小交付范围与验证

最小交付是在一节课中，用一个老师、少量策略和现有白板，完成可被学生反馈改变的教学段落。不是先建设完整策略平台、任意 HTML 组件或长期学习者模型。

固定同一知识点，至少检查下列分支。

- 学生已经理解，老师减少重复并提供适当的新任务。
- 学生出现本课内的具体误解，老师针对误解改变教学。
- 学生明确没听懂，老师改变例子或方法，而非只改措辞。
- 学生要求先示范或暂不回答，老师不持续逼问。
- 学生请求补充准备材料之外的知识，老师可以补充，不机械拒绝。
- 学生在提示下答对，系统不记录为独立掌握。
- 学生打断、刷新或恢复，讲解、板书和待答事项仍然对应。

工程、教学、体验和学习效果分别验证。

| 验证层次 | 需要的证据 |
| --- | --- |
| 工程 | 真实命令、模型与工具记录、事务、版本、取消、恢复和数据保护 |
| 教学 | 内容正确，回应具体输入，教法变化有实际区别，不无证据断言掌握 |
| 体验 | 真实浏览器中的展示顺序、同步、定位、打断和恢复 |
| 学习效果 | 真人独立作答、迁移和必要的前后测，不能用模拟学生替代 |

策略标签变化、schema 通过、板书存在或模型自称学生理解，都不能单独证明教学有效。真实模型验证使用隔离数据和明确预算，保留失败与证据不足的结果。

后续实施按可独立验证的增量推进。详细任务、协议迁移和具体预算写入执行计划，不以本页替代。

## 11. 取舍与待定边界

采用单个持续负责的老师，而不是按教法拆多个 Agent，可以减少交接时目标和上下文丢失。策略按需加载比每次堆入全部指令更聚焦，但会增加工具轮次，需要在真实课例中检查成本。

第一版先保存完整的有界段落，再逐单元呈现，保留现有保存可靠性。代价是段落开始前仍需等待生成。更早展示的增量提交属于后续候选，不因体验目标直接绕过校验和恢复边界。

教师可以总结和建议收束，但教师自动结束课堂、课程完成语义和跨段自主预算仍需单独明确。目标不是在任何时候禁止结束，也不是把总结直接记为掌握。

本设计不恢复已归档的四层教学判断方案，不预设新结构必然提高教学质量。新增状态只服务真实课堂需要，并接受行为验证。
