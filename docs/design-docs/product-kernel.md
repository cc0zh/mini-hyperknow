# 产品内核

状态：2026-10-30 建立。本页是「产品内核是什么」的唯一权威。它定义产品自己持有并负责的东西，不代表相应机制已经实现；实现与验收状态见[质量状态](../QUALITY_SCORE.md)与对应计划。
依据：[DeepTutor 论文内核核查](../references/deeptutor-paper-kernel-check.md)、[先前产品内核调研](../references/deeptutor-product-kernel-research.md)、[同证据探针](../exec-plans/completed/20261029-kernel-evidence-probe.md)。
范围与交付见[产品设计](product-design.md)，页面与交互见[页面与学习体验](learning-experience.md)。

## 1. 定义

> **产品内核 = 两路上下文的持有与装配，加上结果的结算。**

一路是**课程内容**：可重新生成，按版本冻结，决定「这次讲解有没有依据」。
一路是**学习者状态**：累积、可修正，每条指回具体证据，决定「下一步教什么、怎么教」。

每一回合由产品决定注入哪些切片、等待什么结果、结果如何改变下一步；模型负责内容与判读。

判定标准是归属，不是排他：**把提示词整段删掉，仍然存在的机制才是内核。** 不要求内核包含模型做不到的判断，也不以模型变强为内核缩水的理由。

## 2. 三件产品持有的事实

### 2.1 课程内容上下文

课程材料、来源与版本属于产品。生成可以重来，但**同一份判断必须能说明它依据的是哪一版内容**。课程内容不是背景条件：它决定锚定是否成立，因此与学习者状态分开持有、分开装配。

### 2.2 学习者状态（三路）

| 路 | 内容 | 不写什么 |
| --- | --- | --- |
| 表现证据 | 独立做对、提示后做对、未作答、跳过、判不了；来自哪一次交互、哪个题目版本 | 不合成一个掌握分代表全部 |
| 困难清单 | 反复出现的误解、错答模式、活跃与已解决的知识缺口 | 不写跨课程的性格、偏好或标签 |
| 教法尝试记录 | 这次用了什么讲法、学习者实际反馈是什么、下一步换不换 | 不把「已讲过」当「已有效」 |

第三路是独立通道，**不是表现证据的附属**。学习者的正面反馈只是教法反馈，能否独立运用要另留作答证据。

### 2.3 待答事项

哪一项正在等待学习者作答、作答绑给谁、能不能恢复、结果是否已结算。它有自己的生命周期（等待作答／已交未评／已评／作废），不是对话历史里的一段话。

## 3. 装配与结算

1. **装配。** 每回合重建上下文：重读当前目标与相关证据，历史摘要只帮助召回，不代替权威状态。注入什么由产品决定，不是把能搜到的都塞进提示词。
2. **动作。** 讲解、示范、出题并交出作答权、结算一次作答、推进、暂缓、作废重算，都是产品的动作，有前置状态与登记；模型的输出是这些动作的内容，不是决策本身。
3. **结算。** 什么算证据、提示程度如何计入、判不了如何标、重复提交是否幂等、判错能否撤销并重算，规则在代码里，不由模型自述。
4. **闭环。** 双向耦合是定义项：讲解中暴露的弱点要能改变出题，出题表现要能改变后续讲解。单向（练习读讲义、讲义不读练习）不构成内核。

状态更新必须**能指回它读了哪几条具体证据**；对最近一轮做被动摘要不算更新。

## 4. 硬测试

以下四条可以用反例打脸，用来区分机制与提示词：

| 测试 | 不成立的信号 |
| --- | --- |
| 移除学习者状态后重新生成，教学内容与题目是否变化 | 毫无变化 → 该状态只是被写进提示词，未参与决策 |
| 模型正文声称「已掌握，进入下一课」，产品是否照办 | 照办 → 闸门只存在于提示词里 |
| 模型调用失败／超时／不确定，是否被静默存成答错 | 存成答错 → 没有结算规则 |
| 刷新或重启后，「正在等他作答的那件事」是否仍在，且能区分未答／已交未评／已评 | 丢失或混同 → 待答事项没有独立生命周期 |

实测结果与覆盖边界记录在计划中，不在本页维护。

## 5. 不属于内核定义

以下能力允许存在，但**必须作为独立机制候选单独证明增量**，写进内核定义就等于用名词证明有内核：

能力图谱与冻结的能力结构、掌握度分数、及格门槛、整门课程自适应重排、跨产品的学习者画像、向量化痕迹森林、记忆／RAG／多 Agent、复习日历与保持率公式。

其中与旧材料的边界：

- 2026-10-29 用户已取消「掌握度算法、自适应重排整门课程、及格门槛」三项范围限制，**允许做不等于内核要求做**，取消限制也仍不允许无证据认定掌握或通过。强制解锁与 AI 项目自动评审继续排除。
- 旧内核稿的四层方案（能力结构／理解假设／预期改变／判断修正）整体归档为复议材料；仅「教法尝试记录」的最小可做形态（§2.2 第三路）进入本页。
- [同证据探针](../exec-plans/completed/20261029-kernel-evidence-probe.md)未建立「结构化笔记优于完整原始历史」的普遍增量。该结论保留，但**不能据此否定本页内核**：探针比较的是某层结构的增量，本页定义的是产品归属与结算。二者不是同一命题。

## 6. 术语

本仓库只用一个「内核」：

| 名称 | 指什么 | 权威文档 |
| --- | --- | --- |
| **产品内核** | 本页：两路上下文的持有与装配 + 结果结算 | 本页 |
| **Agent 运行时** | 模型调用、工具、上下文预算、权限与会话 | [Agent 运行时 V1](agent-core-v1.md) |
| **教学评测** | 检验业务的工具，不产生产品机制 | [面向学习任务的教学评测](backend-evaluation-pipeline.md) |

「沿用参考产品的交互」是交互与视觉的来源约束，不是内核定义，见[产品设计 §5](product-design.md#5-还原与补齐的边界)。

## 7. 不宣称什么

- 不宣称内核成立等于教得更好。效应需真人前后测，模拟学生只能验证机制是否运转。
- 不宣称所有判断都应由代码做出。教学内容、解释、判读仍由模型产生；本页只界定谁持有、谁执行、谁记账。
- 不以「有保存、有界面、有结构化记录」证明内核成立——那证明的是工程能力。
