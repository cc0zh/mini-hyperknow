# 页面、业务状态与学习体验

状态：2026-10-22 首版目标设计；未实现、未进行浏览器业务验收。
依据：[产品范围](product-design.md)、[参考与缺口](reference-and-gaps.md)；数据及接口分别见[数据模型](data-model.md)、[接口与事件](api-and-events.md)。

## 1. 页面与导航

下列是本项目目标路由，不冒充原站原始路由。

| 页面／路由 | 主要内容 | 成功后的去向 |
| --- | --- | --- |
| 首页 `/` | 文字需求、创建课程；空输入不可提交 | 本次课程创建页 |
| 我的课程 `/courses` | 已创建课程、状态、进度、继续入口 | 课程总览或下一项 |
| 创建 `/course-runs/:runId` | 澄清、阶段、错误、课程就绪结果 | 用户点击进入课程 |
| 总览 `/courses/:courseId` | 简介、单元／讲座／课时、项目和考核 | 用户选择的活动 |
| 课堂 `/courses/:courseId/sessions/:sessionId` | 板书、文字讲解、要点、思考题、插话 | 标记完成后回课程，或进入练习 |
| 练习 `/courses/:courseId/sessions/:sessionId/practice` | 出题、作答、解释、结果、历史尝试 | 看完结果后主动回课程 |
| 考核 `/courses/:courseId/exams/:examId` | 单元目标、答题、提交、结果 | 看完结果后主动回课程 |
| 项目 `/courses/:courseId/projects/:stageId` | 项目上下文、阶段要求、已提交成果 | 明确保存成功后可返回课程 |

常驻导航只保留首页、我的课程及当前课程的必要入口。问答历史在课堂内，活动结果在所属活动内；不额外建设独立聊天历史中心。

沿用 Clone 所反映的页面分工、票券／卡片视觉和白板布局，不引入新品牌视觉系统。样式及局部展示组件可以参考或选择性复用，业务状态不整包照搬。桌面优先，至少保证当前板书可读，不把手机适配作为首版门槛。

## 2. 课程创建

| 状态 | 含义与允许操作 |
| --- | --- |
| `queued` | 已保存学习需求，等待本地模型执行槽；可取消 |
| `clarifying` | 正在生成澄清问题；可取消 |
| `awaiting_answers` | 等待用户明确提交或跳过；不占模型槽，不以静默超时跳过 |
| `generating` | 根据需求与答案生成课程结构；显示实际阶段，可取消 |
| `ready` | 校验并保存的课程已可进入；不等于全部讲义和题目均已生成 |
| `failed` | 请求或内容校验失败，显示原因；可手动重试 |
| `cancelled` | 用户取消；晚到的模型响应不创建课程 |
| `interrupted` | 进程中断了在途运行；可手动重试，不假装仍在后台生成 |

澄清题由真实模型生成，不强制所有主题采用固定四题；题目类型和允许自定义须反映在界面。用户提交后保存问题、选项文字和答案文字，不只传无法解释的选项 ID。

阶段展示来自实际工作开始／完成。没有可计算的分母就展示阶段而非百分比；模型没有返回 usage 就不显示 Token 数。首版可在完整结构通过校验后一次展示目录，不以预设定时器伪装逐单元生成。

重试建立新的 run，保留失败／取消记录并复用已经确认的需求及答案；不覆盖原 run 身份。等待答案的 run 刷新后仍能恢复；已完成 run 重新打开指向同一课程。

## 3. 课程路径与完成语义

- 保留 `Course → Unit → Lecture → Session`；Exam 及 ProjectStage 属于单元，项目目标属于课程。
- 默认展开首单元，其他单元可折叠；不新增前置解锁校验，用户可直接选择活动。
- 采用参考实现已存在的课时完成比例：已完成课时数／总课时数，展示为“课时进度”。考核、项目单独显示状态，不把该比例称作掌握度或全部活动完成率。
- 采用参考实现的下一项顺序：依单元查找未完成课时，其次项目阶段，再考核。总览和侧边继续入口使用同一个结果；若原站进一步证据存在冲突，先登记差异再改规则。
- 课时手动标记完成，或提交一次练习后完成；不要求全部答对。进入练习本身不完成课时。
- 考核是“已提交／已完成”，不是“已通过”；项目是“成果已保存／阶段已完成”，不是“评审通过”。
- 全部课时完成后允许课时进度为 100%，仍清楚展示未完成考核／项目；只有所有活动均无下一项时隐藏继续按钮。

上述比例与顺序来源于 Clone 源码，本项目明确采用，不能写成已独立核实的原站完整规则。

## 4. 白板课堂

进入时加载已保存讲义；缺失则显示真实生成状态。生成失败留在可重试状态，不能出现一块空白画布却宣告就绪。

每个 `BoardStep` 绑定讲解、视觉操作和稳定 ID。文字、公式、代码、框／箭头、列表、高亮、页／栏和 Mermaid 是首版支持集合；不支持的操作在讲义校验时暴露，不静默丢弃。页栏历史可导航，播放写入位置与用户回看位置分开，回看不能让新板书写到错误的历史页。

| 播放状态 | 主要行为 |
| --- | --- |
| `loading` | 载入或生成讲义，不允许推进 |
| `paused` | 已准备或由暂停／恢复进入；下一步只推进一项，继续后开始自动阅读节奏 |
| `playing` | 按本地阅读节奏逐步推进；不是语音时长，也不伪称实际授课分钟数 |
| `answering` | 已保存提问并请求回答；主讲解停止，不接受重复问题请求 |
| `answer_ready` | 回答已保存并完整可读；保持原板书位置，提供“继续课堂” |
| `finished` | 所有教学步骤展示完成；用户仍需选择标记完成或去练习 |
| `error` | 当前操作失败，保留已保存位置和历史，允许重试 |

只有一套播放器控制推进。点击下一步取消旧计时；同一步不追加两次视觉元素。暂停冻结当前文字呈现和后续自动推进。

提问时保存原位置与播放意图；回答成功后不按固定 600ms 覆盖它。用户点击继续课堂才返回：原来播放则继续，原来暂停则保持暂停。问答始终可回看；失败不跳步。此确认恢复是为兑现无语音阅读体验的工程决定，不冒称原站细节。

首次进入从准备态开始；恢复进入停在最近确认保存的步骤并保持暂停，用户自行继续。保存的是步骤位置，不承诺恢复逐字动画中的字符位置。

要点标记只表示讲到，不表示掌握。保留的思考题需实际保存答案并提供相应反馈；选择型可按经校验的标准答案判断，开放型仅提供明确标注的模型反馈，不生成掌握分。不能保留“点击任意选项只关卡片”的假交互。

## 5. 作答、结果与项目

- 练习与考核支持单选、多选、判断，沿用参考的单选即时判定、多选提交判定、答案解释及跳过行为；不新增主观卷自动评阅。
- 最后一题后先进入结果态，不自动回课程。汇总计分与完成标记持久化后仍停留结果页；“回到课程”只导航，不二次提交。
- 显示正确数、得分、星级、连击等个人结果，不显示伪用户排行榜。具体计分见[数据模型](data-model.md)。
- 重新打开优先查看未完成尝试或已完成结果；“再练一次”建立新尝试。默认复用同版本题目，不因刷新重新出题。
- 项目至少需要非空文字或链接；只校验存在性，不访问用户链接或执行提交代码。保存成功才能显示完成，失败保留编辑内容并允许重试。

## 6. 跨页恢复与异常

网络断开不等于取消模型运行。页面重新连接后先确认资源订阅生效，再读取后端已保存快照；订阅与读取期间的通知按 version 处理，旧快照不得覆盖新状态。不能仅凭本地计时器显示后台进度。进程重启不自动重新发起收费调用。

没有课程、没有题目、请求失败、数据缺失分别有明确状态；不把它们全部渲染成正常空列表，不吞错后直接跳转。恢复边界及实例见[真实验收](real-validation.md)。
