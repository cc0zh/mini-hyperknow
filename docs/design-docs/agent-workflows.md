# 模型工作流与课堂上下文

状态：2026-10-22 澄清／课程目录已完成真实模型与内置浏览器的切片验收；课堂、问答和出题仍为后续目标。
关联：[架构](../ARCHITECTURE.md)、[数据模型](data-model.md)、[真实验收](real-validation.md)。

## 1. 核心边界

模型负责生成课程和教学内容，代码负责状态、校验、计分、保存及下一项。主线是显式工作流，不是通用聊天产品，不是多个自主 Agent 相互协商的系统。

复用现有 LLMService／OpenAIService 和消息契约；真正需要动态工具选择时才启用现有 Agent 循环。首版不为了“Agent 项目”把每次生成都包成无必要工具调用，不把示例 read_file 变成资料功能。

## 2. 场景与输入输出

| 场景 | 必须使用的输入 | 输出 | 保存及消费者 |
| --- | --- | --- | --- |
| 澄清 | 原始目标、界面语言 | 有类型的短问题、选项、自定义标记 | run 保存；创建页展示 |
| 课程结构 | 目标、问题文字、所选文字／自定义答案、明确跳过信息 | 课程简介、层级、知识点、考核及适用项目 | 校验后创建 Course |
| 课时讲义 | 课程目标、所在单元／讲座、本课大纲和要点、相邻课时标题 | 有序 BoardStep、讲解和支持的视觉操作 | 保存不可变脚本版本；播放器消费 |
| 课堂插话 | 当前课时及讲义版本、已展示步骤／当前板书文本、问题、本课近期问答 | 对具体问题的文字回答 | 保存 Interaction；不能覆盖主脚本 |
| 课堂思考反馈 | 问题、用户答案、当前课时；选择题已有标准答案 | 确定性判定或明确标注的开放式模型反馈 | 保存反馈，不输出掌握度评分 |
| 课后练习 | 本课真实讲义、要点、期望题型和语言 | 单选／多选／判断及标准答案、解释、来源步骤引用 | 校验并保存 Quiz 版本 |
| 单元考核 | 单元内课时大纲、已保存讲义的相关内容、考核目标 | 单元覆盖的客观题集合 | 保存考核题组；复用答题服务 |

考核允许在未完成所有课时前进入，与参考直接导航语义一致。尚无讲义的课时使用大纲，不假称考核基于已经学过的内容；仍需覆盖单元知识，不随机套题。

项目阶段说明随课程结构形成；提交保存不调用模型评审，不打开链接或执行代码。

## 3. 上下文组织

每个场景构造独立 Context，不把单例 Agent 的可变会话共享给不同课程或并发任务。每次课堂问答从 SQLite 已保存事实重建，不能仅依赖进程内消息数组。

按以下优先级组织课堂输入：

1. 系统约束、语言、当前课程目标。
2. 当前课时大纲和当前问题。
3. 当前及已展示教学步骤；不把未来步骤当成已经讲过。
4. 本课近期已保存问答。
5. 必要的相邻主题摘要；不加载其他课程或全站历史。

首版用有界选择与裁剪，不建设长期用户画像、向量检索、通用记忆或独立压缩 Agent。输入预算来自配置的模型能力上限，未知时使用保守字符预算并明确是估计；不能编造真实 Token。

超限先减少无关历史，保留目标、当前问题和必要步骤。若必要内容仍超限，明确报错并保留数据，不丢当前问题后照常回答。保留被选入上下文的内容／版本依据，便于解释问答为什么得到该回答。

## 4. 结构化输出及校验

首版采用明确 JSON 提示＋Pydantic schema／语义校验，兼容现有同步 provider。合法 JSON 不等于可用课程：还需校验层级非空、ID 唯一、引用有效、步骤顺序、支持的视觉操作、题目答案属于选项等。

- 服务端在校验后生成／规范化持久 ID，不能依赖模型每次输出同一 ID。
- 课程长度和单元数受基本输入预算约束，不固定 5 单元／20 课时；具体上限是运行资源配置，不是教学规则。
- 板书要有真实概念、例子或推导；不能只把目标和“前提／机制／边界”通用句式重复排版。
- 选择题答案和解释必须与题干一致，多选答案集合非空且全部有效。
- Mermaid 是受支持的可视表达，必须真实渲染；源码不可解析就报告并修复，不能默默当普通笔记显示。

无效内容最多进行一次明确记录的真实模型修复：输入原结果及校验错误，再次完整校验。仍失败则 run.failed，保留错误，不截取几个字段拼出“成功课程”。不使用所谓假工具或假 provider 代替真实调用。

## 5. 调用、失败与成本

- 配置沿用 `OPENAI_API_KEY`、可选 `OPENAI_BASE_URL` 和 `OPENAI_MODEL`；展示实际生效模型，不显示不存在的 Venus 选择器。
- 密钥不存在时提前返回配置错误；不读取凭据到前端，不把密钥写进请求快照。
- 首版模型调用默认并发 1，排队可见；取消等待中或在途运行的行为按架构定义。
- 单次模型网络超时初始采用可配置 120 秒；实施时显式约束 SDK 内部自动重试，避免外层“一次”实际隐藏多次收费请求。
- 网络／限额错误不无限重试；用户手动重试建立新 run。结构修复的一次真实调用与网络重试是不同事实，需分别记录。
- 保存 provider、实际模型、prompt／schema 版本、输入上下文依据、原始最终响应、耗时、返回用量与结束原因；未返回的用量为空，不补零或固定值。
- 真实模型调用仍有事实错误风险；格式正确不能替代人工内容核查，不宣称系统保证教学内容准确。

## 6. 现有内核的实施缺口

同步 complete 已通过受控线程接入澄清／造课，场景上下文、结构校验、一次修复、持久化和独立产品 WS 已实现；其他教学场景仍需后续接线。emit 不直接映射产品协议，也不把内部可变对象发给浏览器。

当前 abort 不会中断在途请求；产品已用持久化状态和停服信号阻止后续修复调用，以事务门禁阻止晚到结果生效。SDK 自动网络重试已关闭。未来如增加原生流式接口，必须独立设计增量／最终结果边界并真实验收，不能宣称已经具备。

## 7. 真实验证

使用真实配置调用各场景，核查课程差异、板书知识内容、插话针对性、题目与讲义的关系。结构一致性可断言，教学质量按检查表人工核对；不对非确定性全文做固定字符串快照断言。

既有 Mock 队列、Fake SDK、patch 返回和离线模板不能提供上述证据。验证缺凭据或服务不可用时标记 blocked；澄清／目录成功、取消及恢复的实际证据见[首切片计划](../exec-plans/completed/20261022-real-course-library.md)，结构修复收费路径与后续教学场景仍未真实验收。
