# 模型工作流与课堂上下文

状态：2026-10-22 基线。实现与验收到什么程度见[质量状态](../QUALITY_SCORE.md)；思考题反馈与项目成果仍为目标，不表示 V01–V12 已通过。
关联：[架构](../ARCHITECTURE.md)、[数据模型](data-model.md)、[真实验收](real-validation.md)。

## 1. 核心边界

网页调研工具场景见[网页调研 Agent](web-research-agent.md)，复用 V1 Agent；当前造课的新阶段、全局确认和逐单元展开契约见[蓝图工作流](course-blueprint-workflow.md)，独立调研的历史成功不能替代这条新链路验收。

模型负责生成课程和教学内容，代码负责状态、校验、计分、保存及下一项。课程主线是显式工作流，不是多个自主 Agent 相互协商的系统。独立[即时协助](instant-assistance.md)使用单Agent按需加载可信Skill和调用受控产物工具，不为入口或产物各建一个Agent。

复用现有 LLMService／OpenAIService 和消息契约；真正需要动态工具选择时才启用现有 Agent 循环。首版不为了“Agent 项目”把每次生成都包成无必要工具调用，不把示例 read_file 变成资料功能。

课时讲义一次请求完整脚本，校验失败最多一次完整JSON修复；播放只确认已保存步骤，不逐步生成。narration采用结合实际板书的教师式短段，单步视觉内容建议2–4块；长内容分步而不删要点。提示更新不回写已存v2缓存，用户在课堂生成说明中二次确认后才显式重生；详见[白板课堂](learning-experience.md#4-白板课堂)。

考核允许在未完成所有课时前进入，与参考直接导航语义一致。尚无讲义的课时使用大纲，不假称考核基于已经学过的内容；仍需覆盖单元知识，不随机套题。

项目阶段说明已随课程结构形成；提交保存仍为目标，不调用模型评审，不打开链接或执行代码。考核已实际出题／提交；未来项目行为不因列出就算已实现。

## 提示与执行的维护边界

业务教学指令集中在`src/hyperknow/prompts/`：course负责澄清/蓝图/单元，classroom负责讲义/答疑，quiz负责命题，research负责调研，assistance负责即时教学。生成模块负责模型调用、Schema组合、校验与有限修复；上下文构建留在对应domain，状态/权限/事务留在执行和storage。工具使用细节跟随工具描述，不建通用Prompt框架，不因复用原则共享课程和即时协助会话。

当前删除两个基础教学Skill，但保留可选可信Skill及使用记录；无Skill时正常回答和创建产物。计划/理解检查/建议按需出现，不以字段存在要求每轮发生。新格式不兼容旧请求/快照，不清空既有数据库；本次实施及实际检查见[重构计划](../exec-plans/completed/20261026-teaching-boundaries-refactor.md)。

## 3. 上下文组织

每个场景构造独立 Context，不把单例 Agent 的可变会话共享给不同课程或并发任务。每次课堂问答从 SQLite 已保存事实重建，不能仅依赖进程内消息数组。

按以下优先级组织课堂输入：

1. 系统约束、语言、当前课程目标。
2. 当前课时大纲和当前问题。
3. 当前及已展示教学步骤；不把未来步骤当成已经讲过。
4. 本课近期已保存问答。
5. 必要的相邻主题摘要；不加载其他课程或全站历史。

lesson_context／question_context 直接从 SQLite 事实重建，不依赖内存聊天历史。插话保存教学确认 cursor（初始 -1 表示未开始），并可额外携带当前查看的 anchor_step_id／anchor_object_id；后者必须属于已确认前缀，不回退教学位置。displayed_steps 只包含 steps[:cursor + 1]，绝不把未来步骤作为已讲内容；锚点的具体内容进入真实模型输入。

当前保守预算固定为序列化 JSON 的 60,000 字符，不是模型 Token 上限。先放课程目标、当前课时、讲义版本、问题及全部已确认步骤；必需部分超限返回 context_too_large，不截断问题或静默丢步骤。然后按新到旧选择最多 6 条 ready 问答，历史总量最多 6,000 字符且不得突破总预算，最后按原时间顺序输入。实际选入依据保存在 run.input 和 model_calls.input_basis，不编造 Token 用量。

未来如接入模型能力配置可调整预算；课程工作流当前不接长期用户画像、向量检索、通用记忆或独立压缩 Agent。独立[内核 V1](agent-core-v1.md)虽提供可选会话、显式记忆与摘要能力，但不改变此处 SQLite 事实重建及 60,000 字符业务预算。

## 4. 结构化输出及校验

当前采用明确 JSON 提示＋Pydantic schema／语义校验，兼容现有同步 provider。合法 JSON 不等于可用课程：需校验层级非空、ID 唯一、引用有效、步骤顺序和支持的视觉操作等。本阶段QuizDraft校验选项／答案集合、题型、题量、解释及真实输入来源；合法结构不保证教学正确，仍需人工核查。

- 服务端在校验后生成／规范化持久 ID，不能依赖模型每次输出同一 ID。
- 课程长度和单元数受基本输入预算约束，不固定 5 单元／20 课时；具体上限是运行资源配置，不是教学规则。
- 板书要有真实概念、例子或推导；不能只把目标和“前提／机制／边界”通用句式重复排版。
- 课堂仅接受 `schema_version=2`，不兼容旧课堂：声明 objectives 与按来源要点顺序的 roadmap（短标题、核心问题、来源索引），以 opening 开场、summary 收束；每个路线图要点至少有 explain 与 example，且有至少一个 check。总步数上限36，每步最多6个 operation；page／column 非递减并从1起。来源覆盖、阶段与引用由代码验证，不靠模型自称完整。
- operation 为 text／list／code／formula／box／arrow／highlight／mermaid／table／diagram／circle；每个对象有唯一非空 object_id，diagram节点同命名空间唯一，边只能连接本图节点，强调和焦点不能引用未来对象。table列行维度一致；代码保留缩进，language仅用于code；check有 question 和 expected_answer。
- 生成提示要求先建立本课预期、围绕要点推进并过渡、用具体例子解释机制、检查后回扣路线图；白板凝练结构，讲解补原因、情境与误区。概念课可用比较，流程课可用关系图，公式／代码课需具体推演。不得用重复左右段落凑完整课；Schema不验证事实正确或互补质量，真实课例仍需人工核查。
- 题组3–8题且含single／multiple／boolean；选项ID唯一、正确答案属于选项，多选至少两项正确，single／boolean恰一项且boolean恰两选项。quiz及每题来源引用须属于本次input.allowed_source_refs；来源校验失败也进入仅一次结构修复，不到保存时才发现并额外收费。
- Mermaid 与 KaTeX 是真实渲染，不展示源码假装成功。当前后端校验结构而不预渲染 TeX／Mermaid；前端语法／渲染错误明确报告并允许重试渲染，不自动再收费修复讲义。结构校验失败的一次模型修复与浏览器渲染重试是不同路径。

无效内容最多进行一次明确记录的真实模型修复，再次完整校验。蓝图／单元修复提示采用有界原结果及校验错误，截断必须显式标记，原始响应完整留在model_calls；不能截取几个字段拼出“成功课程”。仍失败则run.failed，保留错误，不使用假工具或假provider代替真实调用。

## 5. 调用、失败与成本

- 配置沿用 `OPENAI_API_KEY`、可选 `OPENAI_BASE_URL` 和 `OPENAI_MODEL`；展示实际生效模型，不显示不存在的 Venus 选择器。
- 密钥不存在时提前返回配置错误；不读取凭据到前端，不把密钥写进请求快照。
- 首版模型调用默认并发 1，排队可见；取消等待中或在途运行的行为按架构定义。
- 单次模型网络超时初始采用可配置 120 秒；实施时显式约束 SDK 内部自动重试，避免外层“一次”实际隐藏多次收费请求。
- 网络／限额错误不无限重试；用户手动重试建立新 run。结构修复的一次真实调用与网络重试是不同事实，需分别记录。
- 保存 provider、实际模型、prompt／schema 版本、输入上下文依据、原始最终响应、耗时、返回用量与结束原因；未返回的用量为空，不补零或固定值。
- 真实模型调用仍有事实错误风险；格式正确不能替代人工内容核查，不宣称系统保证教学内容准确。

## 6. 现有内核的实施缺口

同步 complete 已通过受控线程接入澄清／造课／讲义／课堂问答，场景上下文、结构校验、一次修复、持久化和独立产品 WS 已实现。course／lesson／question／quiz四种run共用一个worker；非course运行直接进入generating，不经过澄清。emit 不直接映射产品协议，也不把内部可变对象发给浏览器。

进入课堂只读快照；明确 prepare 才建立 lesson run，已有有效脚本／运行复用，失败由显式 retry。旧格式只返回 format_error，不解析或迁移；显式 regenerate 才建立替换运行，原字节保存在运行证据中，成功前不替换旧讲义，失败／重启不自动再收费。提问先暂停，再同事务保存问题、查看锚点、was_playing 和 question run；完成回答不改主讲义，明确继续才回到教学位置。check回答复用这条真实持久化反馈链。quiz prepare和再练语义不变；练习无有效讲义明确拒绝，考核不自动生成未缓存讲义。上下文预算及实际input_basis继续留存。项目提交仍为后续目标。

当前 abort 不会中断在途请求；产品已用持久化状态和停服信号阻止后续修复调用，以事务门禁阻止晚到结果生效。SDK 自动网络重试已关闭。未来如增加原生流式接口，必须独立设计增量／最终结果边界并真实验收，不能宣称已经具备。

## 7. 真实验证

使用真实配置调用各场景，核查课程差异、板书知识内容、插话针对性、题目与讲义的关系。结构一致性可断言，教学质量按检查表人工核对；不对非确定性全文做固定字符串快照断言。

既有 Mock 队列、Fake SDK、patch 返回和离线模板不能提供上述证据。验证缺凭据或服务不可用时标记 blocked；澄清／目录成功、取消及恢复的历史证据见[首切片计划](../exec-plans/completed/20261022-real-course-library.md)，不重写为课堂证据。

讲义／问答及练习／考核的真实调用、恢复与检查边界统一见[可靠性状态](../RELIABILITY.md#验证与交付)。本阶段三次quiz真实出题均首次响应通过结构校验、无修复；讲义曾真实修复成功不等于quiz失败修复已验。摄影q_plant_ab忠于讲义但概念待纠正，见[内容债务](../exec-plans/tech-debt-tracker.md)；思考题、项目及全部模型失败时序不能据此算通过。
