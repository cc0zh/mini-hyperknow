## 1. 问题

现有实现能在单次调用内完成讲解、出题与判定，但两次调用之间不传递教学判断：白板课堂与练习／考核各自以"本课时内容"为输入重新生成，学习者在上一次活动中暴露的具体困难不会改变下一次的动作。课程生成阶段声明的课时目标，在课时结束、练习提交之后没有任何地方被核对过。

因此当前的缺口不是功能，而是状态：不存在一份持续存在、能被新证据修正、并因此改变下一步教学动作的判断。

这一问题在 2026-10-29 之前受"不做掌握度算法、不做自适应重排、不设及格门槛"的范围限制而未展开。该限制已取消；取消限制解决的是"允许做"，不回答"做什么"。

## 2. 内核定义

本产品持有并持续修正一份关于"这个人此刻可能怎样理解"的判断。该判断必须能够说明：

- 它的依据是哪些实际表现；
- 哪些表现与它矛盾；
- 还有哪些解释尚未被排除；
- 下一步要获取什么证据才能区分这些可能。

判断不是掌握度分数，也不是对话印象；它是一组可被反驳的假设，连同它们的空白处。

产品因此拥有两项其他做法无法替代的能力：在不确定时明确记录不确定；以及在后续表现不符合预期时，修正自己的教学判断，而不只是修正对学生的评价。

## 3. 内核的四层

### 3.1 能力结构

课程生成阶段声明课程要形成的具体能力，而不只是目录标题。能力结构区分"能按步骤执行""能解释为什么""能识别错误解法为何不成立""换情境仍能选择正确方法"等不同层次的证据，并记录能力之间的前提关系。

**为什么必须由产品持有**：能力结构一旦随每次讲义生成而变化，"是否形成该能力"就无法跨时间回答。讲义可以重新生成，能力结构在确认后冻结。

### 3.2 理解假设

对学习者保留的是有证据的理解假设，而非"已掌握／未掌握"。每条假设同时包含支持证据、矛盾证据、尚未排除的其他解释，以及尚未验证的情境；每条证据必须能指回一次具体的作答、提问或操作。

**为什么必须由产品持有**：模型不持有跨调用的状态，也不会主动保存"我不知道什么"。记录未排除的解释与未验证的情境，是产品必须维护的结构，不是生成能力。

### 3.3 预期改变

每个教学动作在发起前声明它要改变哪一种理解、或获取哪一类新证据，并声明什么观察会推翻这一预期。动作种类不必多，但动作与当前困难之间必须有可检查的对应关系。

**为什么必须由产品持有**：没有可被后续观察推翻的声明，§3.4 无从发生；这一声明的作用不是解释得好听，而是为后续核对提供对象。

### 3.4 判断修正

干预与后续表现配对留证。当表现不符合预期时，需要区分至少四种可能：原诊断有误、所采用的解释未触及真正困难、学生仅在提示下完成、任务本身不足以验证理解。

**为什么必须由产品持有**：修正的对象是产品自己的教学决定，而不是对学生的评价；保留与一次成功无关的完整配对记录，才能避免把单次成功当作方法有效的证据。

## 4. 与现有模块的关系

本内核不新增独立产品面，而是规定既有模块的职责。

| 模块 | 对内核对内核的职责 |
| --- | --- |
| 课程生成 | 在蓝图确认阶段产出能力结构并冻结；课时目标成为理解假设的锚点 |
| 白板课堂 | 在决定下一步讲解前读取活跃假设；提问与回看行为作为证据来源 |
| 练习／考核 | 读取出题前必须针对的假设；判错写入证据，不直接写入分数结论 |
| 即时协助 | 独立会话，可选读写同一份判断；不作为课程进度的替代 |
| 教学评测 | 验证判断的形成、检验与修正过程，而非回答质量 |

## 5. 边界

### 5.1 本版允许什么

2026-10-29 用户明确取消以下三项限制，本内核因此可以使用：

- 依据证据估计掌握程度；
- 依据该估计调整后续内容顺序与练习编排；
- 为课时或单元设定通过条件，并据此决定是否推进。

不在此次取消范围内、仍然有效的排除项：强制解锁、AI 项目自动评审。课程内活动的直接进入规则不变，见[页面与学习体验](learning-experience.md)。

### 5.2 本版仍不宣称什么

以下不是政策限制，而是诚实性要求：

- 不宣称能证明学习效果提升。效应估计需要真人前后测，模拟学生只能验证机制是否运转。
- 不宣称能力结构的生成本身正确。冻结的意义是使判断可比较，不是保证目标无误；结构错误时，后续证据会以很高的置信度指向错误方向，这是本方案已知的主要风险。
- 不宣称单次成功即可归因于某种教学方式对该学习者有效。§3.4 只记录可被推翻的事件，不估计方法效应。

### 5.3 允许不等于要做

授权范围内仍需要按内核价值排序，第一版不应同时落地四层。最小切片候选见 §6。

## 6. 未决问题

### 6.1 已决定：放开两项出题约束（2026-10-29）

一次真实模型对照（同一课程课时、同一模型，各调用一次）显示：把一条手写的理解假设放进现有出题输入后，生成的练习与对照组几乎没有区别，两组都以复述讲义为主。主要原因不在模型，而在现有规则：练习“仅考查当前课真实讲义”，且只有单选、多选、判断三种题型，这正好排除了假设要求补上的两类证据，即新情境中的运用和对原因的解释。单次调用不能排除随机性，所以这个结论只说明“未观察到改变”，不能证明“输入假设无效”。实验材料保存在本地 `data/validation/kernel-ab-20261029/`，不进入版本库。

用户据此授权：

- **新情境题**：练习可以使用讲义原文以外的情境；所考概念与判断依据仍须引用本课讲义，不引入讲义外的事实结论。
- **解释原因题**：允许新增需要学习者用文字解释的题型；作答由模型评阅，结果标注为模型反馈。

上述决定的实施细节仍待确定：新情境题如何校验“只考讲义概念”；解释题的评阅是否计入得分、如何与现有确定性计分共存；仅提供假设输入无效时，是否需要显式要求输出声明所针对的假设条目（见 §3.3）。

### 6.2 仍未决定

以下问题不解决，对应部分无法成立：

- **能力结构如何生成与冻结**：若不能冻结，§3.4 的跨课时比较失去参照，§3.1 退化为目录。
- **证据冲突规则**：支持与矛盾证据并存时，是降低置信度并优先获取区分性证据，还是立即改判。此条不定，§3.2 会退化为随机选择一种说法。
- **"预期改变"如何避免退化成散文**：若不要求声明可观察的推翻条件，§3.3 只是措辞。
- **§3.4 的可断言边界**：在单用户、小样本条件下，可断言的是事件记录，不是效应；文档与产品文案都必须遵守这一区分。
- **最小切片**：目前倾向先只实现 §3.2（理解假设），以现有课时目标为锚点，验证产品能否因此做出模型做不出的判断；其余三层随后。

## 7. 验证方向

本内核的验证对象是判断过程，不是回答质量。可检验的四点：

1. 系统能否发现预先植入的误解，而不是继续按原计划讲解；
2. 系统在证据不足时是否明确记录不确定，而不是输出评估结论；
3. 所选教学动作是否与当前假设存在可检查的对应关系；
4. 干预失败后，系统是否修正判断，而不是重复同一动作。

实现步骤、切片顺序与验收证据留在执行计划中，不在本文维护。

### 7.1 同证据快照探针（2026-10-29）

独立实验已比较完整原始历史、普通摘要和手写理解假设；它未接入产品，不改变本文讨论草案状态。原始历史组已能在若干场景中表达不确定、区分算对与理解、依据新证据重新判断；错误笔记组也能拒绝与原始表现冲突的结论。目前没有建立“结构化笔记带来普遍额外价值”，更没有验证持久判断修订或学习效果。

局部差异提示下一候选验证点是教学动作能否产生区分不同解释的证据，而非仅有没有读取笔记。此为实验方向，不是已确定的产品机制，也不要求每一步都诊断。完整矩阵、失败、预算调整和逐项分析见[同证据探针计划](../exec-plans/completed/20261029-kernel-evidence-probe.md)。
