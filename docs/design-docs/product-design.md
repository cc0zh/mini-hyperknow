# mini-hyperknow 产品设计

状态：2026-10-22 产品范围已由用户确认；2026-10-30 内核定义保留于[产品内核](product-kernel.md)。2026-11-05 用户明确当前交付优先级为一堂完整、白板主导的课，不以两路上下文装配与结算扩建为前置；允许重写，不作旧课堂协议兼容。下述 R01–R11 保留首版边界，实现与验收状态统一见[质量状态](../QUALITY_SCORE.md)。
关联：[产品内核](product-kernel.md)、[学习体验](learning-experience.md)、[架构](../ARCHITECTURE.md)、[参考与缺口](reference-and-gaps.md)、[真实验收](real-validation.md)。

本页只回答范围与交付：首版做什么、不做什么、什么算完成。**「产品为什么这样组织教学」不在本页**，见[产品内核](product-kernel.md)。

## 1. 定位与成功标准

面向个人简历展示的桌面单用户学习应用，实现一门课程从学习目标到讲解、练习、考核与继续学习的完整业务链。交互语义与视觉参考 hyperknow-clone2 的证据，但不是全站复刻，也不是企业级平台。

成功标准是用户能够使用真实模型完成一条学习业务链，并在刷新或重启后继续。页面存在、HTTP 200、结构化数据能解析或演示录像漂亮，均不能单独证明完成。

```text
文字学习目标 → 澄清需求 → 生成课程 → 浏览学习路径
  → 白板分步学习与课堂问答 → 练习／考核／项目
  → 保存记录 → 继续下一学习项
```

## 2. 用户与运行场景

- 使用者：项目作者本人，以及通过作者演示了解作品的面试官；不建立尚未验证的商业用户画像。
- 运行方式：本地单用户 Web 应用，仅以桌面浏览器为适配与验收目标，中文优先；不要求访客注册，不把上线和多用户当作首版完成条件。
- 真实依赖：本地后端、本地持久存储、可用的真实模型服务；个人自用不等于离线模板演示。
- 展示目标：讲清课程生成、教学事件、课堂上下文、活动结果和恢复的一条真实链路，不用企业化术语包装尚不存在的能力。

## 3. 首版范围

| 编号 | 能力 | 必须兑现的行为 |
| --- | --- | --- |
| R01 | 学习目标输入 | 支持非空自然语言需求；创建后能追踪此次生成，不重复创建同一课程 |
| R02 | 需求澄清 | 以选项／允许时的自定义答案补充目标、基础、时间等；选择进入模型输入；允许显式跳过 |
| R03 | 真实课程生成 | 生成与学科和需求有关的课程层级、课时元数据、考核及适用时的项目；展示真实阶段，不编造进度和用量 |
| R04 | 我的课程 | 查看本地课程、完成情况和继续入口；能从真实生成结果进入学习 |
| R05 | 课程路径 | 保留课程 → 单元 → 讲座 → 课时层级，并展示考核、项目阶段；单课内部组织路线图、要点与教学步骤，不改全课程层级 |
| R06 | 白板课堂 | 先路线图，再逐点解释／例子／理解检查，最终回扣总结；白板主导并累积可读图示，右侧文字补充原因与情境，不逐句复述板书；Excalifont／Xiaolai 手写，代码等宽、公式 KaTeX；具备节奏控制、统一图文回看、定位与显式结课 |
| R07 | 课堂问答 | 围绕当前课程、课时、已展示步骤和本课问答回答；暂停主讲解，保留回答，能够继续原课堂 |
| R08 | 课后练习 | 根据本课教学内容生成题目，完成作答、判定、解释、计分和结果回看 |
| R09 | 单元考核 | 围绕单元内容汇集题目，保留考核身份、提交记录和结果；不擅自增加通过线 |
| R10 | 项目阶段 | 展示阶段要求，提交并保存文字或链接成果；可重新查看，完成不等于自动评审通过 |
| R11 | 持久化与继续学习 | 保留课程、讲义、学习位置、问答、作答和成果；各种完成动作统一更新下一学习项 |

练习和考核共享作答组件，不把二者合并成没有上下文的通用刷题页。并非所有主题都必须生成项目，更不能把所有学科的项目固定写成“搭建最小可运行原型”。

### 当前实施优先级

2026-10-23 用户在网页调研真实成功并提交后，授权下一阶段为[调研驱动的全局蓝图确认与逐单元展开](course-blueprint-workflow.md)，并明确不要求旧课兼容。项目成果提交不在本阶段范围内。

2026-10-22 用户确认项目能力暂缓：R10成果提交及R11的成果恢复保留为后续目标。2026-11-05 用户授权完整单课教学四阶段实施，含课堂理解检查的回答／模型反馈与恢复；不扩展为主观题考试评分，不据此宣称V08或完整V12通过。

本次只调整开发优先级：不删除已生成项目要求、不标记项目完成，也不自动改变next_item顺序。未开放项目仍如实提示，用户可从课程目录选择其他课时或考核；是否增加显式“稍后做”导航属于单独的交互决定。

## 4. 明确不做

- 移动端／平板专用适配、触屏专项优化与手机视口验收。2026-10-27用户明确取消移动端适配范围；移动端问题不再列为待修技术债或交付阻塞。已有响应式样式可保留为桌面窗口缩放的降级，不构成移动支持承诺，也不禁止移动浏览器访问。
- 语音合成、语音识别和语音播放；课堂保留文字讲解，不保留失效的音频按钮。
- PDF／其他资料上传、正文解析、OCR、PDF 标注阅读器、资料检索和知识库。用户曾讨论后明确放弃资料能力。
- 独立深度学习模式仍不做。2026-10-24起新增与造课并列的即时协助：独立多轮教学、可信Skill及四类轻量产物；范围与恢复契约见[即时协助](instant-assistance.md)，不恢复资料、检索或课程关联。
- 多人集市、发布交易、社区、分享协作、真实或伪装成真实的用户排行榜。
- 真实支付、订阅、积分扣费、OAuth、公开注册、多租户和企业级权限／安全治理。
- 强制解锁、AI 项目自动评审。2026-10-29用户明确取消此前对掌握度算法、自适应重排整门课程和及格门槛的三项范围限制；取消限制不等于要求全部实现，更不等于允许无证据认定掌握或通过，哪些属于内核要求见[产品内核 §5](product-kernel.md#5-不属于内核定义)。
- 微服务、分布式任务系统、插件平台、通用 Agent 工作台、向量数据库和复杂观测平台。

课程封面首版使用参考风格的颜色与排版，不接图像模型，不展示虚假的“正在绘制封面”。不保留排除能力的占位入口。

## 5. 还原与补齐的边界

1. 已有交互语义和对象层级优先沿用参考证据；不以“教学上更合理”为由私改计分或完成规则。
2. Clone 的模板、占位、错误和静默失败不是必须复制的产品行为。
3. 保存用户提交、正确推进状态、明确错误、刷新恢复等是兑现已有操作的必要配套。
4. 原站未核实的行为不得伪称 1:1；出处和取舍见[参考与缺口](reference-and-gaps.md)。
5. 技术可以重写，交互不能无依据重定义；不要求复刻原站 URL、认证或 WebSocket 的线协议。

## 6. 业务真实性与演示

- 所有生成走真实模型；失败时返回真实失败，不暗中切回固定大纲、通用旁白或固定题库。
- 允许打开此前真实生成并保存的课程来节省演示等待；必须仍具备现场创建新课程的能力。
- 不以预填的唯一演示课程或手工 SQL 结果冒充用户操作产物。
- 直接测试真实计分、状态等函数可以补充验证，但拒绝 Mock、Fake、Stub、录制响应替代真实依赖。
- 没有配置或真实运行证据时标记 blocked／未验证，不能把跳过外部调用写成通过。

## 7. 当前事实与首版完成定义

当前已有 Python Agent 内核、uv 管理的 FastAPI／SQLite 后端，以及首页、创建、课程库、总览、课堂和练习／考核React页面，历史 Mock 路径已移除。造课／课程库已完成两组真实模型与内置浏览器验收，原首切片证据保留，不改写其完成计划。

课堂采用单一新教学协议：路线图、学习目标和 opening／explain／example／check／summary 阶段，稳定对象引用与 table／diagram／circle 等视觉操作；既有文字、公式、代码与 Mermaid 安全边界保留。完整体验及生成约束分别见[学习体验](learning-experience.md#4-白板课堂)与[模型工作流](agent-workflows.md)。普通板书继续使用本地 Excalifont／Xiaolai，代码、KaTeX 和界面字体隔离。每一步经服务端确认后展示，初次／刷新恢复均本地暂停。旧课堂协议不解析、不自动迁移；需要用户明确重新生成，不清库。

分阶段模型／浏览器证据见[可靠性状态](../RELIABILITY.md#验证与交付)。R08／R09既有三题型、显式提交、再练及恢复证据见[完成计划](../exec-plans/completed/20261022-real-practice-exams.md)。本次课堂检查通过真实问答保存回答及模型反馈，不另建 thought-answers 或掌握评分。R10项目提交及成果恢复仍属未来目标；整体状态见[质量状态](../QUALITY_SCORE.md)，不宣称V01–V12全通过或教学全部正确。

首版完成需同时满足：R01–R11 对应行为可操作、排除入口不出现、课程内容具有主题针对性、用户记录可恢复，以及[真实验收](real-validation.md)中的必需场景有实际证据。文档检查通过不是业务验收通过。
