# mini-hyperknow 产品设计

状态：2026-10-22 产品范围已由用户确认。造课／课程库首切片保留真实验收证据；课堂讲义、播放、问答与手动完成已接入，两主题课堂及本阶段练习／考核范围的真实验收已完成。下述首版范围同时保留未来目标，不表示 R01–R11 全部实现。
关联：[学习体验](learning-experience.md)、[架构](../ARCHITECTURE.md)、[参考与缺口](reference-and-gaps.md)、[真实验收](real-validation.md)。

## 1. 定位与成功标准

在 mini-hyperknow 中重新实现 Hyperknow 的核心课程学习体验，以 hyperknow-clone2 的逆向证据和实现为规格参考，交付可真实操作、可解释实现的个人简历项目。不是重新定义学习产品，不是全站复刻，也不是企业级平台。

成功标准是用户能够使用真实模型完成一条学习业务链，并在刷新或重启后继续。页面存在、HTTP 200、结构化数据能解析或演示录像漂亮，均不能单独证明完成。

```text
文字学习目标 → 澄清需求 → 生成课程 → 浏览学习路径
  → 白板分步学习与课堂问答 → 练习／考核／项目
  → 保存记录 → 继续下一学习项
```

## 2. 用户与运行场景

- 使用者：项目作者本人，以及通过作者演示了解作品的面试官；不建立尚未验证的商业用户画像。
- 运行方式：本地单用户 Web 应用，桌面浏览器、中文优先；不要求访客注册，不把上线、移动端和多用户当作首版完成条件。
- 真实依赖：本地后端、本地持久存储、可用的真实模型服务；个人自用不等于离线模板演示。
- 展示目标：讲清课程生成、教学事件、课堂上下文、活动结果和恢复的一条真实链路，不用企业化术语包装尚不存在的能力。

## 3. 首版范围

| 编号 | 能力 | 必须兑现的行为 |
| --- | --- | --- |
| R01 | 学习目标输入 | 支持非空自然语言需求；创建后能追踪此次生成，不重复创建同一课程 |
| R02 | 需求澄清 | 以选项／允许时的自定义答案补充目标、基础、时间等；选择进入模型输入；允许显式跳过 |
| R03 | 真实课程生成 | 生成与学科和需求有关的课程层级、课时元数据、考核及适用时的项目；展示真实阶段，不编造进度和用量 |
| R04 | 我的课程 | 查看本地课程、完成情况和继续入口；能从真实生成结果进入学习 |
| R05 | 课程路径 | 保留课程 → 单元 → 讲座 → 课时层级，并展示考核、项目阶段；不另创教学编排体系 |
| R06 | 白板课堂 | 按步骤呈现文字、公式、代码、基础图形及可读关系图；板书普通文字以 Excalifont 呈现英文／数字／西文标点，以小赖 Xiaolai 呈现中文／中文标点，代码等宽、公式使用 KaTeX 专用字体；有文字讲解、节奏控制和历史板书回看 |
| R07 | 课堂问答 | 围绕当前课程、课时、已展示步骤和本课问答回答；暂停主讲解，保留回答，能够继续原课堂 |
| R08 | 课后练习 | 根据本课教学内容生成题目，完成作答、判定、解释、计分和结果回看 |
| R09 | 单元考核 | 围绕单元内容汇集题目，保留考核身份、提交记录和结果；不擅自增加通过线 |
| R10 | 项目阶段 | 展示阶段要求，提交并保存文字或链接成果；可重新查看，完成不等于自动评审通过 |
| R11 | 持久化与继续学习 | 保留课程、讲义、学习位置、问答、作答和成果；各种完成动作统一更新下一学习项 |

练习和考核共享作答组件，不把二者合并成没有上下文的通用刷题页。并非所有主题都必须生成项目，更不能把所有学科的项目固定写成“搭建最小可运行原型”。

### 当前实施优先级

2026-10-23 用户在网页调研真实成功并提交后，授权下一阶段为[调研驱动的全局蓝图确认与逐单元展开](course-blueprint-workflow.md)，并明确不要求旧课兼容。项目成果提交不在本阶段范围内。

## 4. 明确不做

- 语音合成、语音识别和语音播放；课堂保留文字讲解，不保留失效的音频按钮。
- PDF／其他资料上传、正文解析、OCR、PDF 标注阅读器、资料检索和知识库。用户曾讨论后明确放弃资料能力。
- 独立即时聊天、独立深度学习；问答只发生在课程课堂中。
- 多人集市、发布交易、社区、分享协作、真实或伪装成真实的用户排行榜。
- 真实支付、订阅、积分扣费、OAuth、公开注册、多租户和企业级权限／安全治理。
- 掌握度算法、自适应重排整门课程、强制解锁、无证据的及格门槛、AI 项目自动评审。
- 微服务、分布式任务系统、插件平台、通用 Agent 工作台、向量数据库和复杂观测平台。

课程封面首版使用参考风格的颜色与排版，不接图像模型，不展示虚假的“正在绘制封面”。不保留排除能力的占位入口。

## 5. 还原与补齐的边界

1. 已有交互语义和对象层级优先沿用参考证据；不以“教学上更合理”为由私改计分或完成规则。
2. Clone 的模板、占位、错误和静默失败不是必须复制的产品行为。
3. 保存用户提交、正确推进状态、明确错误、刷新恢复等是兑现已有操作的必要配套。
4. 原站未核实的行为不得伪称 1:1；出处和取舍见[参考与缺口](reference-and-gaps.md)。
5. 技术可以重写，交互不能无依据重定义；不要求复刻原站 URL、认证或 WebSocket 的线协议。

## 6. 业务真实性与演示

- 所有生成走真实模型；失败时返回真实失败，不暗中切回固定大纲、通用旁白或固定题库。
- 允许打开此前真实生成并保存的课程来节省演示等待；必须仍具备现场创建新课程的能力。
- 不以预填的唯一演示课程或手工 SQL 结果冒充用户操作产物。
- 直接测试真实计分、状态等函数可以补充验证，但拒绝 Mock、Fake、Stub、录制响应替代真实依赖。
- 没有配置或真实运行证据时标记 blocked／未验证，不能把跳过外部调用写成通过。

## 7. 当前事实与首版完成定义

当前已有 Python Agent 内核、uv 管理的 FastAPI／SQLite 后端，以及首页、创建、课程库、总览、课堂和练习／考核React页面，历史 Mock 路径已移除。造课／课程库已完成两组真实模型与内置浏览器验收，原首切片证据保留，不改写其完成计划。

课堂代码已实现按需真实生成不可变讲义、八种 operation（text／list／code／formula／box／arrow／highlight／mermaid）、文字旁白、单播放器、页栏回看、暂停提问与显式继续、手动完成及统一课时进度派生。页／栏是步骤位置字段，不是额外 operation。白板字体约定为 FontFace 同时加载本地 Excalifont 与 Xiaolai，使用 `Excalifont, Xiaolai, sans-serif` 字体栈，两者就绪后才测量 Mermaid；代码、KaTeX 公式与界面字体隔离，Mermaid 严格渲染及清洗安全 SVG。字体配置已由后续替换任务取代，当前资源与验收见[字体参考](../references/whiteboard-font.md)，不以原课堂验收证明新字体已验。下一步经后端确认后展示；GET 返回权威播放意图，而初次／恢复前端始终本地暂停。

分阶段模型／浏览器证据见[可靠性状态](../RELIABILITY.md#验证与交付)。R08／R09练习与考核本阶段范围已完成真实验收，含三题型、显式结果提交、再练及作答／结果恢复，见[完成计划](../exec-plans/completed/20261022-real-practice-exams.md)；但不宣称V01–V12全通过或教学全部正确。R10项目提交、thought-answers及完整R11的成果恢复仍属未来目标；R06当前没有可交互思考题，不保留假入口。整体状态见[质量状态](../QUALITY_SCORE.md)，长期成功标准不因此裁掉。

首版完成需同时满足：R01–R11 对应行为可操作、排除入口不出现、课程内容具有主题针对性、用户记录可恢复，以及[真实验收](real-validation.md)中的必需场景有实际证据。文档检查通过不是业务验收通过。
