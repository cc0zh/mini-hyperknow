# 参考证据、差异与必要缺口

状态：2026-10-22 文档基线；以下是静态证据核对与设计决定，不是本项目业务验收报告。
关联：[产品设计](product-design.md)、[外部文档参考](../references/design-document-references.md)、[真实验收](real-validation.md)。

## 1. 证据分级与使用规则

| 代号 | 含义 | 用法 |
| --- | --- | --- |
| U | 用户在本轮讨论中明确确认的范围 | 优先级最高；可裁剪原站能力 |
| O | Clone 中保存的原站编译产物／API 样本，并已局部核对 | 还原具体行为的依据；局部证据不能推出全部原站能力 |
| C | Clone 当前源码或 as-is 文档 | 实现参考；不是原站全部规格，文档中的建议也不是承诺 |
| D | 兑现已确认操作所必需的配套 | 如保存成果、结果停留、错误反馈、恢复；明确是本项目补齐 |
| E | 本项目的工程选择 | 如 Python 后端、SQLite、统一事件通道；不冒充原站技术栈 |

优先采用 U；O 与 C 冲突时不能直接复制 C。只有建议、无证据的新教学能力不纳入首版。本文不重复保存真实账号、用户样本正文、凭据、token 或抓取过程中的会话信息。

## 2. 参考仓库与已核对入口

hyperknow-clone2 为外部只读参考仓库，不是本项目子模块或运行依赖。以下路径均相对该参考仓库，不使用机器专属绝对路径。

| 入口 | 本轮能支持的结论 | 不能据此断言 |
| --- | --- | --- |
| `README.md`、`docs/功能说明.md` | 参考实现范围、已记录的模板／占位／体验缺陷 | README 中“1:1”字样不代表全部真实验收 |
| `web/src/App.tsx` | Clone 实际注册页面，及未知路由回首页行为 | 原站全部页面都已实现 |
| `server/src/types.ts`、`curriculum.ts` | 课程层级、按需讲义、完成比例和下一项规则 | 个性化或掌握度已经闭环 |
| `web/src/pages/CourseJourney.tsx` | 课程路径呈现、直接进入活动的交互 | 原站所有解锁规则已独立核实 |
| `web/src/pages/Sessions.tsx` | 板书、文字旁白、作答、结果回调、项目提交当前实现 | 图像／所有板书操作或成果评审已实现 |
| `server/src/ws.ts` | 生成事件、固定阶段值、白板计时、插话及重入行为 | 百分比、Token 数和自动恢复是真实遥测 |
| `server/src/routes.ts` | 完成接口、成果处理、通用 `stubbed: true` 兜底 | HTTP 200 等于功能完成 |
| `recon/pretty/quizScoring-CUGhpPfb.pretty.js` | O：已核对分数、连击、星级计算及本地伪随机对手 | 排行榜是真实用户排名 |
| `recon/pretty/WhiteboardPage-*.pretty.js` 等 | 进一步核对原站渲染与事件的候选入口 | 本轮尚未对所有分支逐项审计 |

原站路由／端点总数目前主要依据参考 README，不作为本项目覆盖率指标。其他 `recon` 内容仍需按实现问题局部核实，不能将整个目录的存在当作已读证据。

2026-11-10 的[课堂内容生成对照调研](../references/hyperknow-classroom-generation.md)单独固定了当前项目教师回合制、原站现行公开协议与历史有限摘录。证据已保存到仓库，避免再次依赖外部参考库路径；原站后端教法和真实课堂效果仍未验证。本次研究不修改本专题的范围或验收结论。

用户澄清后的目标是[保存原站实际课堂过程](../references/hyperknow-classroom-process.md)，不是把静态对照报告当成生成过程。已保存历史开场，并在用户允许使用现有积分后，录制同一课时的续讲、三次受控输入与教师回应，直到原站本节完成。输入由采集代理所写，不作为用户真实学习表现。以后直接读取仓库内事件、讲解与板书资料，不重复获取原站。

## 3. 明确裁剪

2026-10-24实测核对：原站即时协助的澄清是「一次问多个维度、每张卡各自提交」，本项目保持合并表单一次提交；原站一次网页搜索返回约29条结果而正文不引用出处，本项目不接入搜索，代价是冷门主题的讲解缺少外部语料。原站把`conceptExplanation`、`whiteboardSession`等内部标识符直接显示在界面上，本项目只披露折叠的中文技能名，产物种类也不作为学习者选项。

U 已排除语音、资料上传／解析、知识库、独立深度学习、集市／多人社区、支付订阅、企业级治理。资料能力曾被选择，随后明确取消；旧讨论不能使它重新成为默认需求。原先排除的独立聊天于2026-10-24明确放开为[即时协助](instant-assistance.md)，仅增加教学会话和轻量产物，不恢复全部原站能力。

“完整体验”指裁剪后核心学习链完整，不指覆盖原站全部路由。个人计分可以保留；即使原站对手也是本地算法，也不保留伪用户排行榜。

## 4. 必须补齐的差距

| 缺口 | 证据 | 本项目处理 | 验收 |
| --- | --- | --- | --- |
| 无 key／失败静默降级为通用模板 | C：`ai.ts`、`curriculum.ts` | U+D：明确失败，不回退假内容 | V01、V11 |
| 澄清只传 ID，课程差异有限 | C：生成请求／提示 | D：保留问题与所选文字，进入真实模型上下文 | V02 |
| 阶段、百分比和 Token 使用固定值 | C：`ws.ts` | U+D：实际阶段；未知用量不显示 | V02 |
| 播放循环、暂停和手动推进相互干扰 | C：`ws.ts`／`Sessions.tsx` | D：单一播放器、稳定步骤确认 | V04 |
| Mermaid 仅显示源码，页栏缺少回看 | C：`Sessions.tsx` | D：实际渲染、历史导航与写入游标分离 | V04 |
| 插话只带标题、回答很快被覆盖 | C：`inlineAnswer` | D：本课上下文、保存问答、明确继续 | V05 |
| 思考题选择只关闭卡片 | C：`Sessions.tsx` | D：保留入口则真实接收与反馈，不引入掌握算法 | V05 |
| 最后一题提前调用完成并离开结果页 | C：`QuizRunner.next` | D：提交与结果停留、导航分开 | V06、V07 |
| 成绩、逐题记录和题目版本未保留 | C：完成接口与存储 | D：真实题目、答案与结果持久化 | V06、V09 |
| 项目服务端忽略提交正文 | C：阶段完成接口 | D：保存交付文字／链接，禁止伪评审 | V08 |
| 考核／项目完成后下一项可能陈旧 | C：进度调用位置 | D：所有活动完成统一重算 | V07、V08 |
| 重入课时从头，生成断点恢复不可靠 | C：`stepIndex=0`、resume 分支 | D：步骤快照、run 状态恢复，重启不自动重跑 | V09、V10 |

场景编号的权威定义见[真实验收](real-validation.md)。本表只跟踪要求，不标记任何场景已经通过。

## 5. 不应趁机加入的功能

不因缺少反馈就新增整套掌握度系统，不因项目提交缺失就新增代码执行／自动验收，不因生成耗时就引入分布式工作流，不因原站有端点就保留无业务意义的空壳接口。

## 6. 实施前仍需局部核对

- 白板原站图形／公式／高亮的实际载荷与表现，选择首版支持集合，不虚称全事件兼容。
- 课堂思考题反馈的原站语义；首版必要反馈按本项目明确契约实现。
- 本阶段已局部核对PracticePage／ExamPage含恰好10000ms快答边界，并采用共享个人计分；其他未逐项核对的原站调用分支不能据此外推，出处及本项目检查见[完成计划](../exec-plans/completed/20261022-real-practice-exams.md)。
- 原站样式与静态资源的来源、许可及可复用性；未明确前仅借鉴布局和设计 token，不把整套抓取产物当作当然可分发资源。

上述是实现工作中的证据核查，不改变用户已经确定的产品范围；无法核实的细节标为 E，不重新让用户设计一个产品。
