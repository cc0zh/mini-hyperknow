## 2. 结论先行

**本轮最值得借鉴的不是更多 Agent、RAG、掌握度公式或更复杂的理解假设，而是：围绕同一个学习目标，把真实表现结算成下一次教学的约束。**

DeepTutor 的精通之路把“导师可以自由选择怎么教”和“系统负责什么算证据、哪道题仍待答、能否算通过、下次接哪里”分开。从这些代码能确认的机制，并不以一种裸模型绝不可能作出的理解判断为前提，而是让模型的教学选择进入可恢复、可追溯、可更正的学习过程。这是对源码的产品解释，不是上游宣称的因果效果。[S1–S7]

对 mini-hyperknow 的建议是把下一步从“继续证明结构化笔记比完整历史更聪明”移到“做出一个学习者看得见的局部闭环”。当前探针没有证明笔记的普遍额外价值，应保留这个否定边界；但它没有检验真实活动的编排、提示暴露、恢复、重教与纠错，不能据此否定所有持续学习状态的产品价值。

一个更合适的候选内核表述：

> 围绕一个能力目标，依据学习者刚刚表现出的困难决定下一步；如果这次讲法没有奏效，就改变教学，而不是仅把原讲义继续播下去。

这不是要求每一步都考试，也不是把课程改成强制闯关。学习者仍能提问、暂停、跳过和主动继续；产品必须如实保留“尚未验证”。

## 3. 文档揭示的产品分工：不要把所有东西都叫学习闭环

| 入口 | 实际承担的任务 | 对本项目的启发 |
| --- | --- | --- |
| 书籍 | 从主题／材料编译连贯页面，使用测验、动画、交互等类型化块，并保留页面对话 | 内容组织和呈现是一个产品任务，但生成／阅读完成不等于形成能力；当前课程和白板已有相近基础，不必再造书籍产品 |
| 精通之路 | 围绕能力目标组织知识点和评估依据，跨会话继续 | 最相关的参考，是目标、真实作答、后续动作的联系，不是地图的外形 |
| 练习 | 收集题目，先回忆再揭答案，自评或客观核对后安排复习 | 回忆训练与能力证明用途不同，不能把“记住了”的点击统一解释为系统评估通过 |
| 沉浸式阅读 | 紧贴来源位置讨论、查证、标注 | 来源锚点是机制，不必因此恢复本项目明确放弃的资料上传／知识库 |
| 资料、收藏、笔记本 | 保存可复用输入、原始结果与自己的综合理解 | 输出有后续用途，比单轮增加一种产物更接近产品价值；但本轮不建议扩建这些入口 |
| 全局记忆与学习日志 | 综合个性化事实、偏好，以及目标／会话交接 | 不能把它们与路径里的评估事实合成一个万能画像 |

依据：D1–D9。DeepTutor 同时承担多种学习工作，不代表本项目应同时复制；材料生态和插件／IM 是它的范围，不是我们产品内核成立的先决条件。

## 4. 八个值得深入借鉴的源码机制

### 4.1 下一步来自业务状态，不来自聊天印象

核心调用关系可以压缩为：

```text
精通之路的一次教学回合
  → pre_loop 读取本回合最新路径状态
  → 模型选择解释／追问／出题等动作
  → 服务登记题目与私密判定契约，交给学习者，常规工具批次后停轮
  → 卡片提交绑定题目，运行时先尝试评分；普通文字入口由工具链处理
  → 评阅服务提交证据，导师读取回执与更新状态
  → policy 依据新状态给出下一目标和建议动作
  → 导师继续教学
```

具体实现：[S1] 给出下一目标；[S3] 定义持久问题／交互；[S4] 是公开工具入口；[S5] 提交评估；[S6] 每回合注入新快照与已有评分回执；[S21] 在卡片入口尝试导师生成前的预评分。待答题具有独立生命周期，而不是上次聊天里提到过的一段话。恢复时能区分“等待作答”“已回答待评阅”和“已经评完”。这是静态实现支持的语义，未实测所有恢复故障；出题后的停轮也有同批工具与已流出正文边界，见 §4.8。

一个重要限定：policy 中具体的讲解／练习动作是给模型的建议，并不证明模型必然采用最佳教法；默认目标顺序主要仍是模块／知识点顺序，不是一个已证明有效的全局自适应课程规划器。

**可借鉴：** 保存当前正在完成的教学事项，并让它约束后续调用。相比多加一段历史摘要，这直接改变产品能执行什么、何时结束、从哪里恢复。

### 4.2 不同能力需要不同证据，而非所有主题统一刷选择题

知识点分为事实记忆、程序技能、概念理解和开放设计四类。[S3] 在 [S1] 的系统评估规则中，前两类走量化门槛，后两类走解释性评估；概念／设计卡片的答对，并不会自动替代对自己的解释的评估。注意这是“评估通过”的规则，不是所有导航推进的唯一条件：明确的学习者掌握声明是另一条路径，见 §4.7。

公开的解释评估入口不是直接采纳导师提交的通过布尔值：工具忽略这个兼容参数，读取当前真实学习者消息，交给服务评阅。结果分为正确、部分、不正确和暂不评分；不确定或调用失败不能简单存成答错。[S4–S5、S7]

**局限必须同时读：** 当前量化门槛是 0.9；分数是近期作答加权并限制小样本上限，不是经校准的知识追踪概率。[S1–S2] 解释性通过可以直接设置定性通过状态，不能据此断言稳定迁移能力。评阅器自报的置信度阈值也不是评分可靠性证明。

**可借鉴：** 先问“本课目标要用什么表现来验证”，再选择活动；暂不复制阈值、知识点全图或四类型完整体系。用户已授权的新情境题和解释原因题，是本项目现成的切入点，但当前运行代码仍未接入。

### 4.3 学科依据、学习表现与教法反馈是三种不同状态

DeepTutor 至少把三件事分开：

1. **内容依据**：一个目标／题目／答案由哪些实际来源支持，来源是否仍有效。[S8]
2. **学习证据**：学生实际答了什么、结果是什么、是否用了提示、来自哪次交互。[S3、S5]
3. **教学反馈**：学习者明确偏好，以及某个知识点上的局部困难／教法尝试。[S9]

第三类尤其接近当前“理解假设”的讨论，但做法更克制：推断与学习者报告分开；策略结果有未知、帮助了、未帮助；记录必须局部归属到知识点。它不直接授予掌握分。偏好与观察分别最多 6 条和 12 条，常规状态只取相关观察；明确报告的依据要求逐字出自本次学习者消息，而不是导师自证“我已经讲过，所以有效”。[S9]

**可借鉴：** 第一版不用建设完整心理模型。先把“这次用过什么讲法、学习者实际反馈是什么、下一步要换什么”做实。学习者说“这个例子让我懂了”仍只是教法反馈；能否独立运用，要另外留下作答证据。

### 4.4 判断必须能被撤销；辅助成功不能冒充独立表现

量化掌握计算排除作废和非独立作答；有提示的成功会在证据质量中受限。[S5] 学习状态也区分已讲解、辅助下练习、尚未独立表现、独立表现等，不把播放位置直接当理解。[S1]

题目／答案键出错时，服务能够作废或改键，并重算该知识点的有关状态与复习安排。两个读到的完整性测试还明确检查只撤销对应题目的证据，而不误删其他题目的记录。[S5、S10] 这些测试未在本次运行，不能称为通过。

**可借鉴：** 与其优先承诺“我知道你掌握了多少”，先兑现“我不会拿提示后的复述证明你会了，也不会在题目错了之后继续把它算作你的问题”。这是容易展示、也容易被反例检验的产品承诺。

### 4.5 目标寿命长于对话；摘要只能帮助召回，不能取代权威状态

每回合会重新读取当前目标状态；学习回合用精简工作简报，只展开当前目标、待答题、必要前提和少量到期复习，编辑大纲时再读取完整地图。[S4、S6] 历史摘要不是当前快照。

长会话的教学摘要保留来源交换的归档标识，超出预算可回读原记录，并要求区分学生表现与导师声称。[S11] 这段要求首先是摘要契约，不代表摘要内容已经被证明正确。

全局记忆则另有 L1 工作区镜像、L2 分界面整理、L3 综合的管线；文档明确承认当前 L3 通常只引用整个 L2 界面，不是精确端到端事实链。源码中的近期活动召回还刻意只读时间戳和标签，不读取学生答案正文。[D9、S12] 因此不能说“建了全局记忆，就已经有可信的教学判断内核”。

**可借鉴：** 先用现有 SQLite 的课时／活动身份作为学习事项的归属；按任务注入相关事实。暂不做跨所有功能的长期学习者画像，也不因这次研究打破即时协助的独立边界。

### 4.6 调整路线与安排复习是两种明确机制，不是无边界自主规划

改纲采用真实替换引擎的预览：保存新旧差异及状态摘要，再提交那份已保存的草案；版本变动或结果不匹配会拒绝，避免在聊天中口头说改好了。[S5 的 1922–2031 行] 这是可审阅的变更协议，不等于每次答错就自动重排整门课程。

main 的路径复习调度读取结果、提示、时间与保持状态，同一学习时段的重复成功不会无限增加保持稳定性。[S13] 题库“练习”另有 SM-2 风格冷启动日程；开发文档明确不称其为 FSRS。[D6、S14] 两者不要混写成同一个经过验证的算法。

dev 另外增加按路径绑定的复习策略：四种预设和自定义模板，绑定保存模板快照，改模板不会静默改掉旧路径的日程；评分及跨界面保持更新也改为读取该绑定。[S15] 这是 dev 差异，不是本次 main 的默认实现。

**可借鉴：** 让教学策略、学习者选择及变更影响可解释。复习可以是闭环形成之后的延伸，不宜现在把日历、通知和复杂保持公式一起搬进来。

### 4.7 继续学习的权利与“系统证明你会了”必须分开

补充复核发现一个容易被门槛叙事掩盖的事实：`is_assessed_mastered` 与 `is_mastered` 不是同一个判定。前者核对系统评估；后者也接受 `learner_mastery_overrides`。`mastery_source` 和单目标报告保留这个区别，导航可以前进而评估分数不变。[S1、S19]

| 事件 | 改变什么 | 不应被解释为什么 |
| --- | --- | --- |
| 系统评估通过 | 评估状态，通常也允许路线推进 | 不等于已证明长期保持或跨情境迁移 |
| 学习者明确声明已掌握 | 独立声明记录和路线推进；不改已有作答证据 | 不是系统评估通过 |
| 学习者要求暂缓知识点 | 优先转向其他未完成知识点，并撤下相关待答任务 | 不把该知识点记作掌握；其他项目处理完后仍可返回 |
| 学习者跳过一道题 | 当前题目生命周期 | 不能直接推导为整个能力已掌握 |

API 的 override 命令调用 `set_learner_mastery_override`，后者只写独立声明；`defer_objective` 则另存暂缓记录并处理待答项。policy 的测试也明确使用“分数 0.2、系统未通过、声明来源 learner、路线前进”的反例，但本次没有运行该测试。[S19]

源码中的门槛注释与教学提示词不能替代全链路：提示要求导师不要假称通过，不能据此推断学习者 UI／API 没有自主声明渠道。本次核实后端接口与返回字段；未完成浏览器实测，不断言每处界面都正确显示来源。

**对本项目的直接启发：** 将“播放／活动完成”“是否有独立表现”“学习者选择下一项”视为不同事实。可以保留手动完成与自由进入，不必为了形成教学闭环先加入强制关卡。首切片只显示未验证、辅助下完成、独立作答记录等诚实状态；是否采用上游的“自声明掌握”措辞另行决定，不直接照搬。

### 4.8 教学中的“轮到你了”应成为执行协议，而不只是口头邀请

`mastery_quiz` 保存题目后设置 `card_posted`；共享循环在工具批次结束后检查该标记，以空最终输出结束常规路径。题目公开投影移除答案键，工具事件也过滤敏感参数。它确实比只写一句“请作答”多了一层实现，但仍不能声称完整防泄答：[S20]

- **停轮不等于取消同批调用。** 普通工具在同一批并发执行，出题不是先于其他普通工具的独占栅栏；若同批还有暂停工具，调度先处理暂停。不能只照搬“把出题工具放最后”的文案。
- **隐藏答案键不等于模型不知道答案。** 出题模型本来就生成判据；已经流出的导师正文不会撤回。能否不提前提示答案仍需要提示约束与真实反例检查。
- **真实用户文字不等于绑定的答卷。** 卡片入口有 `question_id`，持久答案优先、已评分交互可回放；普通文字工具可省略题号，未见答案必须晚于出题回合的硬校验。组题的子串校验也不证明片段语义上对应那道题。[S21]
- **模式检查不等于用户授权。** `outline/study/review` 在后端限制相关工具；但缺失／未知模式有兼容放行，模型又能用工具切换模式。因此它是工作流边界，不能直接当成“用户没同意就绝不改动”的安全边界。[S22]

这些是静态调用链中的限制，不是已复现的漏洞或已发生的误评分。值得移植的是协议目的，而不是直接复制实现：**登记任务 → 让出作答权 → 接收绑定回复 → 提交一次结果 → 消费结果决定下一动作**。如果本项目实施，应明确拒绝同批出题兼评分，用题目身份、内容版本和出题后的回复绑定作答；普通讨论、引用答案与真正提交分开，不能只信模型填写的 answer 字符串。

## 5. 哪些宣称需要保留边界

- **评分有结构不等于教学正确。** 量化门槛、少样本上限、评阅置信阈值都是当前政策；本次没有其校准、可靠性或真人收益证据。
- **存在旧函数不等于当前公开链路仍使用它。** grading.py 仍有相似度／关键词启发式；公开开放解释入口实际走语义评阅。只 grep 到旧函数就断言整个产品按关键词判理解，会误读源码。[S4–S7、S16]
- **来源约束有适用范围。** validate_evidence 在没有选定 PDF 来源范围且没有依据包时可以返回；不能泛化成每一目标、每一回答均强制经过外部来源核验。已有范围时则检查目标与来源指纹、权限及覆盖范围。[S8]
- **跨界面记录不等于自动赋予掌握。** assessment 服务仅接受可验证的路径／知识点关联；非路径证据主要更新关联的保持／复习状态，不能说任意聊天或自评都可自动通过目标门槛。[S17]
- **测试不等于效果。** 语义评阅相关测试大量使用 monkeypatch 模拟评阅，适合验证事务、失败处理和输入隔离意图，不证明真实评分正确；本项目也不能照搬其测试方法冒充自身真实验收。[S18]
- **论文不等于开源代码。** 本仓库已有参考指出上游 RAG eval 不是 TutorBench 实现；本次不借论文效果为上述规则或本项目背书。
- **静态追踪不等于跑通。** 本次没有复现浏览器交互、模型输出质量、取消恢复或全部引用权限。结论分为源码事实、由此得到的产品推断和待试验建议，不混成已验证能力。

### 6.1 对“为什么停滞”的更谨慎解释

草案中的“模型不持有跨调用状态”只描述裸调用；本项目课堂与即时协助已经传递历史，即时协助还单独保存继续步骤。因此不能把“两次调用间完全没有判断”“只有结构化假设才能表达不确定”当成已证明的缺陷或产品独占性。

同证据探针的三组共享原始事实与专用判断提示，**不是直接对现有课堂 prompt 做线上对照**；它证明了几种能力并非假设组独有，也暴露内容错误与过度追测，没有证明某层结构普遍无效。此前两次出题未观察到区别，也不足以把原因完全归结为题型限制：客观题同样能承载新情境，尚缺控制变量验证。[探针方案](../exec-plans/completed/20261029-kernel-evidence-probe.md)

建议改变成功问题：不要先问“我们的判断是不是裸模型做不出来”，先问“同一个模型，在真实作答、暂停、刷新、改判和后续教学中，能否可靠地完成一项学习任务”。这是本轮产品推断，不是新基线决定；教学质量仍需另验，可靠保存也不能代替教对。

## 7. 推荐下一切片：一个课时里的反馈驱动教学回合

### 7.1 先兑现一个可见承诺

学习者明确表示卡住或请求试一试时，系统能围绕本课一个能力继续工作；必要时获取区分性作答，改变讲法，再检查，而不是回到不变的播放序列。

候选流程：已有一段讲解 → 学习者反馈／请求检查 → 简短、不过早给答案的任务 → 真实作答 → 解释、澄清或改变讲法 → 新情境下再试 → 明确继续／暂缓／保留未验证。

不是每个步骤必考；学习者只问定义就直接解释，只想继续也不强制锁住。最初可把它放在现有课堂的局部支线中，保留不可变主讲义和播放位置，不重建课程页面，也不默认改动课时完成规则。

### 7.2 最少需要持有的内容

- 一个本课能力锚点及内容版本；从现有课时目标中选一个，不先扩建整门能力图谱。
- 当前开放的任务和私密参考／判据；真实作答、提示暴露、结果、来源与状态必须可恢复。
- 一条局部教学记录：此前怎么解释、学习者实际说／做了什么、什么仍不确定；只在后续调用确实需要时结构化。
- 下一动作及其依据：为什么继续讲、换例子、查前提、再试或结束；由产品约束证据与提交，由模型处理教学内容。
- 无法评分、未作答、跳过和不正确分开；保存失败不能算完成，错误判定可撤回。开放题模型反馈与原客观题分数分开，首切片不偷偷混算及格。

这些是候选行为要求，不是已批准数据库 schema，也不要求新增一套通用 Agent 内核。

### 7.3 与现有探针衔接的例子

仅作设计示例，不是本次运行结果：学生把“2 米加 30 厘米”算成“32 米”。当前仍可能是不会换算，也可能会换算但没统一单位。

下一动作先请他独立把 30 厘米换成米，而不是先告诉他换算答案。会换算时，教学转向为何相加前要统一单位；不会换算时，先补换算。之后换一个数值／情境再试，并记录是否获得帮助。

这里有用的差异是**实际获得了哪种可区分表现、它是否改变教学**，不是题目输出里是否引用一个假设 ID。模型看到原始历史也可能做得很好；若如此，应保留原始事实而不是为了证明结构化层有用继续加层。

### 7.4 为什么不是先做其他三个方向

| 方向 | 价值 | 本轮建议 |
| --- | --- | --- |
| 反馈驱动的局部重教／检查 | 学习者立即感知，能利用当前课堂、问答、SQLite 和新题型授权 | 优先验证，是一个切片而非三个新页面 |
| 全课程掌握图谱与自动重排 | 长期潜力，但依赖目标稳定、评估可信及真实使用证据 | 暂缓；当前并非被禁止，只是缺少先做它的证据 |
| 全局记忆综合与画像 | 可能支持长期连续性，但会引入误记、过时与范围问题 | 暂不建设；先验证课时内局部事实确实被消费 |
| 多模态产物、更多 Agent／工具 | 丰富表达与外部能力 | 不是当前断点；当前白板／动画能力已经不能由此自动形成学习闭环 |

### 7.5 先验收机制，再谈教学收益

若后续实施，复用现有真实业务与学习任务评测入口，不再新建一套大评测框架：

1. 同一初始目标、能力依据和模型，比较原固定课堂、能读原始表现的普通教学基线、候选闭环；基线也应得到同样可用事实，不通过剥夺上下文制造优势。
2. 真实执行后续交互。分叉后的学生回复要来自实际交互，不把固定的后续材料伪装成某次新动作造成的结果；模拟学生只验证运行机制。
3. 检查不同表现是否导致有理由的不同动作，以及动作有没有先泄露答案；检查一次未答／“懂了”是否被误判为掌握。
4. 检查教法无效后是否改变、已经展示能力时是否能停止无谓追测、明显错误判定能否撤销、刷新／重启能否继续同一任务且不重复计分。
5. 记录不确定与失败，不仅展示成功案例；内容正确性和评分合理性需独立核查。少量真人使用可以发现摩擦，不能据此宣称统计学习收益。

**推进条件：** 学习者能看见系统确实利用了自己的表现；反例下状态诚实；比普通多轮基线更可靠地完成上述活动，而不制造明显不必要的考试或等待。

**停止／简化条件：** 如果原始历史已经足够，而结构化记录没有带来恢复、范围约束、纠错或动作连续性的额外价值，删除那层；如果主观评分仍不可信，保留解释性反馈而不参与通过判定；如果区分性问题只是把答案喂给学生，先改教学任务，而不是扩建画像。

### 7.6 把建议收敛成用户可感知的交付，而不是又一层状态表

**候选产品承诺：**“你卡住时，这节课会围绕这个困难陪你完成一次尝试；你离开再回来，它知道刚才在等你做什么。你选择继续，也不会被记成已经学会。”这是拟议承诺，尚未实现或获实施授权。

最小演示不需要新的入口群：在现有课堂答疑支线内，明确区分“继续讨论／提交本次作答”和“返回主课堂”；主讲义及播放位置不改，分支只锚定一个课时目标。先完成三件事：

1. **接住任务。** 生成一个可恢复的待答事项，私密参考与公开题面分开，展示后把下一步交给学习者，而不是继续替其回答。
2. **用到表现。** 真实提交得到反馈；不会换算时补换算，会换算但没统一单位时补连接；“没帮助”时换讲法，“已经独立做到”时允许结束，而不是永远追测。
3. **诚实收尾。** 未答、跳过、辅助成功、独立成功和无法评分分开；允许返回主课，不悄悄改写活动完成或掌握结论；纠正题目或评分时保留修改依据。

不先开工能力图谱、全局画像、全课程重排、复习日历，也不通过把独立即时协助接入课程来凑闭环。若这个局部承诺不值得使用，再完整的理解假设 schema 也不能替它证明价值。

验收需分层进行，避免用工程恢复能力冒充教学更聪明：

| 验收层 | 应检查什么 | 不能推出什么 |
| --- | --- | --- |
| 任务机制 | 在出题、提交后未评完、评完后三个位置刷新／重启；不丢待答项、不重复结算、不改主课完成；拒绝旧版本或错题号提交 | 机制可靠不代表评分或教学正确 |
| 证据诚实 | 提示后复述、“懂了”、未作答、引用答案、要求暂缓、错误答案键等反例；允许不判和更正 | 结构完整不代表形成了能力 |
| 教学增量 | 同模型、同原始事实、尽量相同交互条件下，与普通多轮教学比较实际后续动作、是否换法及是否无谓追测 | 不把基线剥夺历史／原有恢复能力，也不把模拟学生结果宣称真人收益 |

这里“错题号拒绝、重复提交不重复结算”是绝对行为要求；同一已提交操作应幂等返回已有结果，不必把正常重试当错误。不靠把基线做坏来获得优势，结构化判断的额外教学价值另做对照。若普通多轮已经同样好，保留能带来恢复、纠错和身份绑定的最小业务状态，删除无额外价值的假设层。若只发现评分不可信，就先保留反馈、不赋予通过结论，而不是扩建更多评分模型来包装不确定性。

本轮只建议将这个最小切片作为下一讨论／实验对象，不启动收费实验、不改主流程，不把本文当成已同意重定义整个产品。
