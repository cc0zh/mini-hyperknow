# DeepTutor 论文内核部分核查：两路上下文装配与画像三路

## 3. 主要发现

### 3.1 内核是两路上下文的装配，不是一份学习者状态

论文 §2 把个性化引擎定义为**两种互补上下文**的联合：

| 半边 | 回答 | 论文机制 |
| --- | --- | --- |
| 静态知识锚定 | *课程教什么* | 源材料切成原子单元 → 知识图谱 + 稠密索引双路检索 → 倒数排名融合 → 去重后按预算截断，得到 `C_rag` |
| 动态个人记忆 | *这个学习者怎么学过* | Trace Forest + 学习者画像，装配成 `C_mem` |

每步前装配 `C_mem`，与 `C_rag` 在总预算内动态分配。**这不是「一份学习者状态给讲解和练习共用」，而是课程上下文与学习者上下文各有生命周期与装配规则，再在每一步被拼起来。**

对内核定义的直接后果：只写「维护学习者状态」会漏掉另一半——课程内容的版本、来源与可追溯边界同样属于产品持有物，且它决定「这次讲解有没有依据」，不是背景条件。

### 3.2 画像有三路，其中「教法反思」是独立通道

§2.1.2 把学习者画像写成三路并存：

- **会话历史**：覆盖过哪些主题、怎么解的、表现趋势。
- **困难清单**：反复出现的误解、错答模式、**活跃或已解决**的知识缺口，每条带证据。
- **教学反思**：哪些讲法用过、效果如何，用于指导后续交互。

第三条是先前调研完全未提的，而它恰好是仓库[旧内核稿 §3.3](../design-docs/kernel-teaching-judgment.md#33-预期改变) 所说「预期改变」的最小可做形态：记下这次用了什么讲法、学习者反馈是什么、下一步换什么。它不需要认识论结构，只需要一条可指回具体交互的记录。

论文同时排除了另一种做法：**画像不是对最近一轮的被动摘要**。三条专门记忆通道各自查询历史、跨会话比对，才更新画像；原文称这是「工具介导的分析过程，而不是单遍文本总结」。操作含义是：状态更新必须能指回它读了哪几条具体证据。

### 3.3 注入按角色切片，注入什么是产品决策

`C_mem` 由两条通道装配：活跃痕迹检索（预算按层分配）＋按角色摘取画像（规划者取会话历史与困难清单，写作者取教学反思，出题者取困难清单加历史题型）。

**「往哪一步注入什么」是产品持有的决定**，不是「把能搜到的都塞进提示词」。这一点与通用 Agent 运行时按预算压缩历史不同：它决定的是哪些**学生事实**进入哪一类教学判断。

### 3.4 闭环是双向的，且是产品级约束而非措辞

§2.4：讲解中暴露的弱点写入困难清单，直接影响下一批题目；题目表现再回写会话历史与教学反思，改善后续讲解。

这与仓库旧讨论「讲解与练习互不可见」的缺口描述正好相对：**双向耦合是内核的定义项，不是加分项。** 单向（练习读讲义，讲义不读练习）不构成内核。

### 3.5 论文自己的边界：§3 的扩展不是被验证的核心

§3 把同一套 substrate 扩展到书籍、Co-Writer、Mastery Path 与多渠道 Partner，并在 Limitations 明确：这些扩展是**架构实例**，其对保持率、参与度与真实学习结果的影响需要纵向真人研究。

因此内核只借鉴 §2 的装配与闭环，不把书籍、Co-Writer、Partner 当作内核成立的条件；这与先前调研 §3「不要把所有东西都叫学习闭环」的结论一致。

## 4. 必须纠正的误读：消融比较的不是结构化状态与原始历史

§5.4 的消融是**有记忆 vs 完全没有记忆**：

- 去掉静态知识锚定 → 内容锚定显著下降（依据性、来源忠实度、跨概念）。
- 去掉动态个人记忆 → 适应性显著下降（个性化、契合度）。
- 两者都去掉 → 降幅最大，说明两者互补而非可互换。

它**没有**比较「结构化画像 vs 完整原始历史」。仓库[同证据探针](../exec-plans/completed/20261029-kernel-evidence-probe.md)做的正是后一种对照，并得出平局。

两者不矛盾，但也**不能用论文为探针翻案**：论文证明的是「有学习记忆比没有记忆好」，探针回答的是「在同等原始事实下，多一层结构化笔记是否比完整历史更有价值」。前者是内核存在的证据，后者是某层结构增量的证据。借论文立内核时，只能引用前者。

## 5. 论文与仓库实现的差异（分别记录）

论文描述 Trace Forest 为多分辨率、每节点带稠密嵌入、可语义检索的树；三个工具分别做近似最近邻检索、按时间／任务／主题筛选、读取完整内容与祖先路径。

固定提交的实际实现是**三层文件式记忆**：

| 层 | 实际形态 |
| --- | --- |
| L1 | 按界面与 UTC 日期切分的追加式 JSONL；写入失败被记录并吞掉，不阻断产生方 |
| L2 | 每个界面一份 Markdown 摘要，带脚注引用 |
| L3 | 四个固定槽位：`recent`／`profile`／`scope`／`preferences` |

界面为 chat、notebook、quiz、kb、book、partner、cowriter；`recall.py` 的交互路径**只读时间戳与标签**，不读消息正文、文档正文或答案，注释明确这是它能被交互路径安全调用的原因。

结论分三层写清楚，不合并且不互相否定：

1. **论文事实**：设计上存在多分辨率、可语义检索的痕迹森林。
2. **仓库事实**：该提交用文件式三层记忆 + LLM 驱动的 L1→L2、L2→L3 归并实现，交互期召回刻意不读正文。
3. **不可推出**：不能据论文描述认定实现具备向量检索，也不能据实现文件形态认定论文机制无效。

对本项目的意义：**要借鉴的是「分层痕迹 + 可追溯归并 + 按角色注入」，不是「向量森林」。** 后者在仓库里不是可移植的已实现能力。

## 6. 附录 B 的两处实现细节

- **B.1 闭环算法**是会话级：每轮先重新装配记忆上下文，再按任务分支执行，结束后追加一棵痕迹树并更新画像。**状态在会话之间累积，装配每轮重做**——这是「摘要只帮助召回，不取代权威状态」的实现含义。
- **B.2 主动 Agent 循环**是三段：装配上下文 → 有界工具循环 → 持久化并在接近预算时归并旧消息。它说明多渠道与主动触达不改变内核，只是同一循环的另一个入口。

## 7. 对本项目的候选结论（不是实施授权）

1. 产品内核应表述为**两路上下文的持有与装配 + 结果结算**：课程内容（可重生成、按版本冻结）与学习者状态（累积、可修正、每条指回具体证据），而不是单一的「学习者状态」。
2. 学习者状态至少分三路：**表现证据、困难清单、教法尝试记录**。第三路是独立通道，与表现证据分开存放、分开消费。
3. 状态更新必须**能指回它读了哪几条证据**；被动摘要不算更新。
4. 双向耦合是定义项：讲解中暴露的弱点要能改变出题，出题表现要能改变讲解。
5. 判定「机制还是提示词」的硬测试来自 §5.4 的构造方式：**移除学习者状态后，教学内容与题目是否变化**。不变则不是内核。
6. 不移植：向量化痕迹森林、书籍引擎、多渠道 Partner、掌握度阈值；这些既非已验证内核条件，也超出当前产品范围。

上述候选的产品化表述与边界见[产品内核](../design-docs/product-kernel.md)。
