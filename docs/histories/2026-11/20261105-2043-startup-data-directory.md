# 修正本地启动数据库目录

## 用户诉求

后端启动时报“数据库来自更新版本，拒绝降级打开”。用户明确选择只清理启动配置，使用现有v3数据库，保留全部课程和会话，不重置数据库。

## 根因与修改

- 本地`.env`的`HK_DATA_DIR=eval_result`指向v7数据库，而当前代码只支持至v3；启动命令、依赖和ASGI入口本身正常。先前仅核对命令与依赖，漏查数据库版本。
- 仅将本地配置改为`HK_DATA_DIR=data`，其他配置不改；产品代码、版本拒绝保护和数据库结构不改，不作兼容转换、降级、合并或清库。
- `data/hyperknow.sqlite3`保留3门课程、4份讲义、2个即时协助会话；`eval_result/hyperknow.sqlite3`原v7库保留1门课程、0份讲义、3个即时协助会话。没有访问受保护旧评测子目录。
- Windows故障排查增加版本不匹配与环境变量优先级说明。

## 验证

- `Settings.load()`确认有效数据目录已为`data`、数据库版本为3。
- 使用SQLite backup生成现有v3库的临时一致副本，实际启动Uvicorn/FastAPI并得到`GET /api/health` 200；测试子进程禁用模型和搜索凭据，无新增模型调用。
- 两份原数据库全部应用表的行数与内容摘要前后一致，v7版本保持7；测试服务已停止，临时副本已移除。没有把测试副本启动宣称为正式8000端口服务已运行。
- 首轮只读验证因Windows路径键分隔符断言失败，尚未启动服务；统一路径键后重验通过。证据为忽略目录`data/validation/startup-config-20261105-204310/result.json`与`backend.log`，不包含凭据。
- 本轮无产品代码改动，不重复跑全量模型或教学验收；收尾执行文档骨架与差异空白检查。
